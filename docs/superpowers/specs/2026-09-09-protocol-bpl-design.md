# 上传 protocol 的 BPL 形式化与人工核对

状态：**approved；源代码与隔离安装验收已完成。最终公共提交 CI/合并结果见 PR #95；正常预览尚未升级，不代表完整产品科学验收。**
日期：2026-09-09。本文是保留的稳定设计；公开验收入口为
[Web validation history](../../validation/web_preview_20260905.md)，施工过程保留在 Git history。

## 1. 要解决的问题与明确非目标

让研究者看清上传方案规定了什么步骤、条件和阶段，哪些信息缺失，以及每一项来自哪里。
LLM 负责提出 BPL 草稿；确定性编译器负责它实际支持的形式检查；研究者负责原文与实际实验语境的核对。
三者不能替代彼此。方案规定的目标不是测得的细胞身份，方案步骤不是本批样本的执行记录。

### 对 BRIDGE 的实际意义

BRIDGE 评估分化产物，而不是执行培养实验。BPL 在这里首先是可核对的“计划过程上下文”：
把阶段、操作和原文条件关联到来源，使研究者能指出哪一段适用于当前样本、哪一项仍缺失。
首期的实际使用者是现有 intake 的 protocol 核对页面，不是科学工具、评分器或机器人。
价值验收应看原文遗漏和参数歧义是否更容易被发现、补充是否可追溯；不以 BPL 行数或编译通过率衡量。

必须分开三层：方案规定的过程、研究者提供的本批执行事实、转录组实际观察。
前两层能够帮助提出关于预期阶段和批次差异的问题，但不能替代第三层的独立证据。
培养 D28 不等于人胎 GW/PCW；相同方案不等于独立重复；不同方案与实验室/批次混杂时不能作因果归因。
未来受控的方案差异比较和产品目标讨论可以利用版本化表示，但本期不实现自动比较、
目标窗口推断、marker/prior 构造或向普通模型上下文扩散原始方案。

本期包含上传文本、BPL 草稿、真实编译结果、缺项追问、可读步骤和人工核对版本。
不接机器人、仪器、实验执行或模拟执行；不训练模型，不新增科学评分或正式生物学重复判定；
不自动确认产品资料，不自动生成/批准/运行分析，不追溯改写旧会话。
现有样本的已确认批次答案保持不变；测试填写的起始细胞不能转成真实生物学声明。

## 2. 选择与上游依据

采用“现有已配置 LLM + 固定版本的作者 BPL 编译器 + BRIDGE 来源/覆盖范围检查”。
另一条路线是绑定论文专用模型；公开仓库不直接提供该权重，因此不作为首期依赖。
不把现有阶段摘要 JSON 改名为 BPL，也不另造一套实验工作流引擎。

固定研究基线：BPL 2.4.0，提交 `4e505740f5025d59ba655c6c955f83876f753007`，MIT。
上游要求 Python >= 3.13；编译器使用独立服务器环境，不升级当前 BRIDGE 共享运行环境。
独立 Python 3.13.14 环境已实际完成安装、加载和 Linux 编译；15 个合成案例的 45 次 parse/validate/lower 调用验证了下列限制。这不是复现上游模型或论文实验。
主文全文访问受限，本设计参考论文摘要、作者公开仓库及下列固定版本源码。

以下限制已在上述固定提交上实际复现，不推论整篇论文无效：

- `lower_program_to_plan` 只选取第一个 protocol；不能把多方案文件的其余内容视为已检查。
- `if`、`for`、`while` 中的步骤可未进入计划，外层存在可编译步骤时仍成功退出；须独立清点遗漏。
- `_emit_call_statement` 可将其它调用转换成 HumanStep；这类操作不是已获参数/容器状态验证的步骤。
- 缺失、符号或负等待时长可变成 1 秒；`wait(duration: 10 mL)` 可变成 10 秒。BRIDGE 不采用这些值。
- `transfer(volume: 1 mL)` 的产物为 1 uL；10 mM 也可被当作 10 uL；未知容器可自动映射到 plate_1 孔位。这些不是可信实验参数。

因此首期不使用“方案验证通过”这一总标签。展示“语法检查”“上游编译结果”“来源与覆盖范围”
和“人工核对”四项独立状态，并保留未检查项。上游文档列出的能力不是 BRIDGE 已验证的能力。

## 3. 用户流程

上传 protocol → 生成带来源的 BPL 草稿 → 编译与覆盖范围检查 → 必要时追问 → 用户核对并保存版本。

1. 复用现有 PDF、Word、文本上传和提取入口。每个附件独立形式化；多附件不静默拼接为一个方案。
   旧附件首次打开不自动重跑；只有新的上传、显式重试或补充回答才生成新版本。
2. 页面默认显示步骤、原文给出的时间/条件、来源页码或段落、编译诊断与待核对事项。
   BPL 原文和检查记录可展开/下载；用户不必读代码。原始时间表达与原文保留，
   不能拿取样 D28 推断培养阶段起止时间。
3. 缺失或歧义项一次问一个，说明对应步骤和原文。选择题都提供“其他（自定义输入）”；
   也允许“暂不确定”，保留未解决状态。用户补充标为用户声明，不能冒充原文已有。
   最新有效回答必须由生成步骤引用，生成时应进入可读内容和 BPL；已被替换或“暂不确定”的回答不能当作条件。
   保存回答不等于已纳入表示，引用齐全也不等于语义正确，仍需核对实际步骤。
4. “保存核对版本”只表示研究者检查了当前表示及其剩余缺项；不是确认已执行实验。
   允许保存仍有未检查/未知内容的版本，但页面持续标明限制；这不会阻塞独立的原有资料草稿流程。
5. 修改附件、回答或 BPL 草稿后，先前版本继续保留，新版本重新检查；不继承旧版本的通过/核对状态。
   对话内后续科学工具仍走现有独立资料确认和运行审批，本期不自动消费 BPL 生成科学事实。

## 4. 组件与数据合同

沿用现有 intake 生命周期、认证、会话锁、工作线程与取消/过期结果防护，不新增队列或常驻服务。

- 现有 provider 增加专用形式化输出合同：带出处的有序 BPL 步骤片段、缺失/歧义项。
  服务器从唯一片段序列生成固定 protocol、完整 BPL 与物理行号，不要求模型另写整份代码或映射。
  每个片段的字符串、注释和括号必须自身闭合，不能跨步骤改变词法解释或逃逸到另一个 protocol。
  保留完整多行字符串原字节；固定语法的调用参数、map/list 不接受排版换行，服务器只把表达式中的
  非字符串/非注释排版换行规范为空格，再生成行号。非空白符号、注释及其行终止符不变，重复规范化结果不变。
  这是表示层的确定性处理，不是模型补全条件、改变操作或证明语义正确。
  使用现有配置的模型及正常凭据；不调用上游带额外工具权限的自动研究工作流。
- 一个私有 formalization 模块负责生成、版本、追问和结果持久化。
- 一个窄编译适配器调用固定版本上游程序，返回 AST、编译诊断和检查范围。
  不给 LLM 选择命令、执行路径、输出路径、编译目标或任意参数的权限。
- 页面增加可读 protocol 核对组件；现有 IntakeWizard 接入入口，不把整个资料表单重写。

每个私有版本至少记录：

| 内容 | 必须绑定的信息 |
|---|---|
| 来源 | upload ID/hash、protocol ID/hash、提取器版本、文本范围、截断状态 |
| 生成 | 实际模型标识、提示版本、generation/revision、生成与修正次数 |
| 表示 | BPL 原文/hash、步骤 ID、BPL 行范围、原文 source ID/位置、用户补充 |
| 检查 | 上游提交/版本、适配规则版本、退出码、逐项诊断、未覆盖操作/语句/参数 |
| 核对 | 未核对或用户已核对、用户动作时间、所核对版本的精确 digest |

原始文件不改写。BPL、AST、可读视图和诊断都放在该会话的追加式私有版本目录，
通过原有受控资产/下载边界返回；不把私有绝对路径、原始样本标识或凭据发给模型/公开导出。
步骤来源映射保存在旁文件，引用必须由服务器校验并取回原文，不信模型提供的引用正文。
这不是公开 Scientific Schema，也不是 ProductDefinitionCard、ToolRun 或执行证据。

## 5. 生成、检查与错误处理

- 每轮最多一次初稿加两次修正，共三次模型请求。只允许有原文或用户补充支持的内容；
  语法/标识修正可自动尝试，新增或改变浓度、时长、材料、顺序等实质内容必须有相应来源，
  无依据则转追问。不能为编译通过删除步骤、填默认值或把真实步骤改成人工占位。
  自动修复使用封闭补丁合同，可更新既有步骤的代码片段、既有问题的选项，或追加遗漏的已有来源编号；
  仅语法或编译失败时允许改片段，服务器同步重建完整 BPL 与行号。编译已通过时不得借选项或补引用改代码。
  用户另行确认了只增补引用的边界：旧引用及顺序不变，不改原文、步骤内容、参数或顺序；
  新增编号必须来自本次提供的来源，拒绝未知编号、重复补丁/新增编号及总引用数超限，并重新执行全部来源检查。
  数字缺乏引用支持时提供对应步骤、数值和单位，不自动猜测该用哪一处来源。
  用户随后批准修复漏问：对已编译但未解析、且没有待回答问题的等待时长，在同一三次预算内单独核对来源。
  核对回复只能追加对应步骤的来源问题，或提供该步骤所引用原文中明确给出时长/结束条件的逐字片段。
  编译器不理解字符串不等于原文缺失；缺失或不确定应保留问题，不修改旧问题、步骤和代码，不填默认数值。
  未完成核对不发布完整版本；明确的“暂不确定”继续保持缺项，不自动重复追问。
  核对结果绑定服务器提供的步骤及具体诊断行、列；同一物理行的多个调用分别保留，不能互相消除缺项。
  核对结果与原回复进入私有尝试记录；这是有边界的模型复核，不保证发现任意协议的所有语义缺项。
  服务器保留初稿的步骤 ID/可读操作/出处、问题与排除记录，不要求模型重新生成这些事实。
  未知或重复修复目标及额外实质字段被拒绝，原始回复、已应用补丁与重建草稿分别保存在私有尝试记录。
  在解析或应用前流式保留最多 1 MiB HTTP 解码正文，并记录捕获字节数、SHA-256、状态码和截断标记；
  超限/中断时只称有限前缀，不称完整回复。不保存请求头，不公开或回传这些原始审计字节。
  无效回复不替换上一个草稿及其编译诊断，剩余修正仍据真实诊断进行；无响应时不伪造正文记录。
- 复用当前提取文本边界与隐私过滤。超长/截断内容明确显示“仅部分内容”，
  不声称整份文档已形式化；扫描 PDF 无可提取文字时请求文本版，不自动引入 OCR 服务。
- 生成 BPL 上限 128 KiB，每版最多 200 个可读步骤；上限是首期资源政策，不是论文指标。
  达上限返回明确限制，不截掉后声称完整。
- 编译阶段使用固定参数的 parse/validate/lower、human 目标；禁止 simulate、执行器、robot 导出和任意 shell。
  不运行上传的 BPL/Python；BPL 只交给受控解析/编译接口。外部 import、模块加载及附件提供的文件路径不接受。
- 编译进程使用最小环境，不继承模型 API key、登录 token、用户 HOME 或 provider 配置。
  只在自己的临时工作目录写产物；每次 30 秒、内存 512 MiB、返回产物合计 8 MiB，
  超限/内部异常记为 unavailable，不伪装为方案语义错误，也不自动扩大预算。
- BRIDGE 检查源步骤是否在 AST/计划/未覆盖清单中逐项交代；
  HumanStep、未处理语句、多 protocol、缺失等待时长及未经验证的单位转换必须阻止全面通过标签。
  原文覆盖的统计是对已提取范围的清点，不是完整语义保真的证明，最终仍需人工核对。
- 首期展示的可读条件来自带来源的表示，不直接采用可能被上游默认值/单位映射改变的计划字段。
  非受支持操作保留原文及 BPL 草稿，明确“未检查”，不强制改写成貌似可执行的动作。
- 数据/附件/回答 revision 改变、取消请求或会话忙碌时，旧结果不得覆盖新草稿；
  UI 保留上次完整版本和失败原因，显式重试，不无限循环。
- 各状态独立保存：任务 pending/running/complete/unavailable/cancelled；
  语法 not_run/passed/failed；编译 not_run/passed/failed/unavailable；
  来源/覆盖范围 complete_for_extracted_scope/partial/needs_input；
  人工核对 unreviewed/reviewed。不存在自动 biological_validated/executed 状态。

## 6. 实施与验收顺序

1. 先在独立服务器环境安装固定上游版本，用真实编译器运行公共最小例子和小型合成反例。
   重点覆盖错误单位、体积换算、空时长、未知调用、多 protocol、条件/循环语句、未定义容器、
   操作降为 HumanStep；逐例记录实际结果与本期可声明的检查范围。
   如果无法安全、如实地区分已检查/未检查，保留草稿功能但不开放编译通过标签，报告阻断点。
2. 对缺失参数、伪造引用、步骤遗漏、私有路径/import、超时超限、过期结果和旧答案保留先写失败测试，
   再实现最小适配；不修补整个上游编译器、不另写完整编译器。
3. 用当前配置 LLM 真正完成一个公开/授权的非敏感 protocol：记录所有生成版本、真实编译诊断、
   来源映射和人工核对入口。Mock、论文现成评估产物、编译器安装成功不能代替该证据。
4. 精确安装包验证 + 真实浏览器桌面/手机流程：上传、查看出处、回答“其他”、刷新恢复、
   修改后旧确认失效、保存核对版本；检查无自动资料确认、无分析计划/实验执行、旧会话数据保持不变。
5. 汇报源代码、安装后行为、真实模型与真实协议覆盖分别达到哪一层；完整产品评估和生物学验证仍独立。

用户已核对并批准本文。实现已经完成源代码与隔离安装验收；本设计保留批准后的合同与编译器行为边界，公开验收见上方记录，施工时间线由 Git history 保存。
“其他”选项修补与 BPL 科学含义仍是不同验收项。
