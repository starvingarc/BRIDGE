# BRIDGE 总体路线图

状态：已批准的建设路线，不是已完成能力清单。更新：2026-10-14。

## 目标与唯一维护源

BRIDGE 面向细胞治疗产品的研究性评估，首个完整应用是 hPSC 来源中脑多巴胺能产品。产品行为以 [PRD](BRIDGE_PRD.md) 为准；本页只维护实施顺序、依赖和交付条件，不另写一套产品合同。

| 问题 | 唯一维护源 |
|---|---|
| 哪些源码可公开获取 | 本仓库 `main` 及其公开提交 |
| 尚未公开的开发工作在哪里 | 维护者保留的开发分支与受控记录；不包含在此源码快照中 |
| 哪些内容已经公开 | `starvingarc/BRIDGE` 已批准的公开版本 |
| 分析使用什么科学资源 | 既有资源定义、来源登记及后续版本锁定文件 |
| 内部真实数据和验收证据在哪里 | 机构受控存储；不进入 GitHub |
| 线上实际运行什么 | 部署清单中的软件提交、构建产物摘要和资源版本 |

软件源码、科学资源、用户数据、部署配置分别管理。私有仓库不是私有数据仓库；开发权限不自动授予数据权限。公网部署与源码公开是独立关口，经过审核的私有版本也可用于获批托管服务。

## 阶段总览

| 阶段 | 交付目标 | 主要依赖 | 完成后进入 |
|---|---|---|---|
| 1 私有协作建立 | 可追溯代码、协作者、清楚的开发起点 | 工作区盘点与敏感内容审查 | 可移植开发 |
| 2 开发与科学资源标准化 | 无需内网也能开发；资源可识别和检查 | 私有仓库与资源来源 | 完整 PRD 建设 |
| 3 完整 PRD 产品建设 | 真正的产品评估、证据与用户闭环 | 适用工具、资源和科学审阅 | 软件候选发行 |
| 4 可复现发行 | 软件、资源和结果版本对应明确 | 已集成代码与分层验证 | 公网产品化交付 |
| 5 公网产品化 | 多用户安全地上传和分析自己的数据 | 资源边界、部署设计 | 邀请试用部署 |
| 6 公网邀请试用 | 可访问、可维护、可恢复的托管服务 | 完整 PRD 适用流程验收及机构批准 | 扩大使用或公开发行 |
| 7 公开发行与持续维护 | 可安装、可引用、可复核的公开版本 | 公开许可与论文相关审查 | 持续发布与维护 |

阶段 1 最先交付。阶段 2 支撑阶段 3；阶段 4 的构建准备可与阶段 3 同步推进。部署条件调查可以提前开展，但不能用账号、容器或下载功能替代产品评估主线。完整 PRD 验收先于公网邀请试用；条件性模块须用适用案例验证，不能全部标成 unavailable 后宣布完成。

私有研究版 0.3 采用限定发行范围，见[版本与发布](RELEASE.md#03-私有研究版范围)。
它交付现有单产品研究流程的解释修订和可追溯报告，不以版本号宣布阶段 3 或公网阶段全部完成。

## 1. 私有协作建立

**目标：**校外合作者不依赖学校账号即可参与代码开发。

- 盘点整个服务器工作区；保存原始 Git 历史、未提交增量和发布来源记录。
- 审查后迁移唯一开发主线；部署快照与未验收增量先保全，再经明确授权整合有效增量，不能将合并视作科学资格。
- 邀请既定协作者，配置可用的分支保护、PR 与 CI；不把套餐不支持的保护写成已启用。
- 提供协作、数据、发布入口；只清理确认已保留且无活动依赖的施工目录。
- 上传前完成工作区与 Web 职责收敛：根状态索引区分开发、运行与待整合来源；归档已结束工作树；针对存储、产物访问、执行和 HTTP 职责拆分现有中心实现，不改科学行为。低耦合协作遵守 [AGENTS](../AGENTS.md#实现原则)，当前结果见迁移状态 (controlled historical record; not distributed)。

**责任：**维护者负责迁移、权限和整合；协作者确认能够访问仓库。

**交付：**私有仓库、迁移状态、受控恢复材料、协作者邀请状态。

**完成条件：**结构收敛经定向验证和审查后才上传；独立克隆可还原代码，未验收成果有明确位置，公开仓库、原启动入口、版本指向和数据关系未被改变。已有 BRIDGE 预览服务按明确授权关闭，不自动恢复。候选功能合入主线仍需独立审阅。仅创建仓库、备份或增加索引不代表此阶段完成。

## 2. 可移植开发与科学资源标准化

**目标：**合作者在干净环境中能启动、开发和执行主要工程检查。

- 统一开发入口和依赖说明；替换对个人目录、既有会话和隐式环境的依赖。
- 合成产品与 reference 已独立交付，见[协作数据](../examples/demo/README.md)；继续完成其完整流程验收，并使用来源和许可明确的公开集成数据、内部真实数据建立三层验证。
- 沿用现有资源 ID、Tool Card、环境规范和 reference registry，收敛资源身份、版本、来源、许可、校验值、科学状态及兼容关系。
- 实现资源列举、安装或手工登记、校验和功能就绪检查；缺失资源时指出影响，不展示伪造结果。
- GitHub CI 不依赖未发表数据；内部受控验收运行经审核的准确提交，只回传允许共享的摘要。

**责任：**工程维护者负责开发环境，科学工具负责人负责资源与适用性，数据负责人审批共享范围。

**交付：**开发说明、测试数据入口、资源获取和锁定方案、分层检查。

**完成条件：**新合作者无需内网账号就能完成一次合成流程；至少一个获准公开的真实案例可复现；资源缺失和校验失败可解释。安装成功不等于科学验证通过。

## 3. 完整 PRD 产品建设

**目标：**研究者围绕细胞产品获得可核查的测量、解释、比较与下一步建议。

| 工作包 | 内容与依赖 | 可核查交付 |
|---|---|---|
| 资料、事实与计划 | 研究问题、数据与 protocol、必要追问、事实确认、审批、QC 和资格更新；保留已有有效实现 | 明确事实来源、不重复追问、QC 后资格与计划一致 |
| 五个核心评估域 | 目标身份、区域身份、发育相容性、完整制剂与非目标组成、增殖及应激；七类程序分别处理 | 真实测量、完整分母、适用性与缺口；不将候选标签直接称为产品纯度 |
| 资源与多产品比较 | 多来源参考审阅、公开产品登记、比较对象推荐和确认、版本对齐及稳定性 | 合格比较对象、背景对象和排除原因；以 sample/preparation 为单位 |
| 知识增强与条件性分支 | 调控、功能程序、代谢、检测转化、通讯与空间支持；获批 linked graft 独立后验分析 | 对适用样例实际运行；区分 measured、inferred 和 prior-only，不回填移植前结论 |
| Agent 与证据反馈 | 工具输出经校验入图，保留支持、反对、冲突、缺失及同源关系；选择能区分假设的下一工具 | 图检索、实际 ToolRun、写回和解释更新构成闭环，非固定工具菜单 |
| 用户结果与修正 | 多维画像、交互证据图、已有工具图件、同版本报告、事实修正及局部重算 | 用户可追查来源；旧证据保留；页面与报告表达同一版本 |

**责任：**科学工具与资源、Agent 编排、Web 交互、证据与可视化四条实施线；总控维护共享接口与统一验收。具体人员按任务认领，不替协作者预先承诺工作。

**交付：**一份以 PRD 条目为索引的实现与验证记录，每项链接真实代码和证据。未完成工作继续放活动计划，不重复散落在多个进度文档。

**完成条件：**单产品、比较、条件性知识增强与 graft、修正流程有适用案例；至少湿实验使用者与实现者共同走查。真实数值、来源、单位、版本和声明边界一致。科学资格独立记录，未经验证的评分不因上线而晋升，不提供临床安全、疗效或放行结论。

工作台（湿实验主线）的功能按用户使用顺序分为 A 准备方案、B 记录实验、C 看单个样本、D 比较、E 解释与下一版、F 报告与输出、G 移植后与 X 平台与验收，
逐项状态、对应 issue 与实施顺序只在[用户旅程与功能路线](../plans/user-journey.md)维护；GitHub 上每段一个 milestone，功能 issue 带 `roadmap` 标签。
本页不复制这些条目。

Agent 上下文管理保留为单独工作包：任务状态与聊天历史分离、工具产物外置、事实版本与压缩后来源保留。在该任务正式开始时再调研和设计，不夹带进仓库迁移。

## 4. 可复现软件与资源发行

**目标：**同一版本可以安装、复核和回退，不依赖某个服务器工作树。

- 正式候选版从已合入主线的准确提交产生；统一软件版本来源。
- 构建 wheel、源码包及部署镜像；镜像不含用户数据、凭据或私有运行结果。
- 科学资源独立版本化；大型资源用获准分发渠道，受限资源提供授权获取与登记说明。
- 记录软件提交、镜像摘要、工具与环境、reference、知识快照、测量规范和输入摘要。
- 设置预发布、用户验收、正式发布和回退流程；代码回退不等于数据库或会话回退。

**责任：**维护者负责构建与发布，科学负责人审核资源及科学声明，用户完成产品验收。

**交付／完成条件：**独立环境可恢复同一软件与资源组合；版本、变化和限制可见；已有版本不原地覆盖。版本号由实际发布决定，不预设 v1.0.0 日期。

## 5. 公网产品化

**目标：**在保留科学合同的前提下，支持不同用户安全使用。

- 共享 token 改为独立账号和邀请机制；项目、数据、任务、图、附件和报告逐项鉴权。
- 长任务与 Web 请求分离，具备排队、取消、失败恢复、配额和资源限制；执行目录隔离。
- 为并发服务选择事务元数据存储、私有对象存储和持久任务机制；旧会话采用显式导入规则。
- 上传进入受限暂存与校验流程，验证文件内容、大小及解压／逻辑资源消耗；支持适用的大文件恢复机制。
- 默认不将原始矩阵发送给外部 LLM；结构化摘要也需按字段最小化并核对供应商与数据使用条件。
- 实现数据保留、主动删除、临时文件回收、备份清理和日志脱敏。

**责任：**Web／服务端与部署维护者；涉及数据处理边界时由机构负责人员确认。

**交付／完成条件：**账号隔离、越权拒绝、任务取消恢复、大文件及配额、删除链和故障恢复通过验证。默认单一代码库、少量服务组件，不以前置 Kubernetes 或自建身份系统增加负担。

## 6. 公网邀请制科研试用

**目标：**获批用户通过链接上传自己的获准研究数据并完成分析。

- 决定运营主体、托管地区、学校批准环境或商业云、预算、容量和维护负责人。
- 确认接受的数据类别、上传授权、供应商、数据存储与传输边界；按实际地区和数据要求完成机构及专业审查，不把免责声明当合规证明。
- 配置域名与 HTTPS、测试／生产隔离、秘密配置、监控、告警、备份和恢复。
- 提供隐私说明、使用条款、研究用途边界、保留与删除规则及联系渠道。
- 邀请制起步，记录真实使用问题、算力开销、失败率与支持负担，再决定是否扩展开放程度。

**责任：**项目负责人协调机构与预算；部署负责人维护运行；科研用户验收产品。

**交付／完成条件：**完整 PRD 适用流程已验收，数据处理边界获确认，获邀用户能完成真实流程，运维人员能处理故障与恢复。公网可访问不等于完成上线。

## 7. 公开发行与持续维护

**目标：**论文与合作约定允许后，提供可安装、可引用的公开软件和资源。

- 审核代码、文档、示例、许可、贡献归属和资源再分发；不直接公开私有开发历史与讨论。
- 从批准版本生成公开发行快照，记录私有来源与公开提交、内容清单、构建产物之间的对应关系。
- 保留现有公开历史；提供 Release Notes、安装与资源说明、CITATION、漏洞报告及维护渠道。
- 修复回到私有开发主线，经审查后单向公开；部署始终使用准确版本，不维护另一套服务器代码。

**责任：**维护者负责软件发行，项目与科学负责人批准公开范围及声明。

**完成条件：**公开安装可复现、许可完整、资源可获取或限制明确；公开版本和托管版本的对应关系可核查。扩大公网注册范围另设决策，不自动启用。

## 验证与推进原则

按变更风险分层检查：合成合同、公开真实集成、内部真实验收、科学验证、服务安全及恢复。复用同一代码／环境的有效保存证据，不为迁移重跑全部科学计算。结果正确性、用户隔离、敏感内容审查与恢复属于必要验证。

各阶段启动时确定实施清单和排期；未落实的服务器、预算、科学数据与审阅条件明确作为依赖，不编造完成率或日期。
