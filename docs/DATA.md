# 数据与科学资源

## 四类内容分开管理

| 类别 | 保存方式 | GitHub 内容 |
|---|---|---|
| 软件与小型获准资源 | Git、软件包 | 源码、合同、测试代码、允许分发的小资源与小型合成协作数据 |
| 大型或受限科学资源 | 按来源条件保存在受控或获准分发存储 | 身份、版本、来源、校验值、许可、适用功能与获取说明 |
| 用户数据和派生结果 | 用户／项目约束下的私有存储 | 不上传原始文件、会话、私有回执和敏感截图 |
| 部署配置 | 私有配置或秘密管理设施 | 仅字段说明和无凭据示例 |

私有代码访问权不等于真实数据访问权。公开可下载也不自动意味着允许再次分发；未声明许可时保留待确认。访问链接不得包含长期 token、签名参数或账户凭据。

## 沿用已有维护源

科学身份和用途以 [Data / Reference Registry](bridge_spec_v0.1/data_reference_registry.md)、[基础资源矩阵](registries/BRIDGE_foundation_materials_matrix_20260713.tsv)、[包合同](tool-contract.md)、[知识策展说明](../knowledge/README.md)及[环境规范](../environments/README.md)为准，不新建一套平行人工资源注册表。

资源身份与校验值从上述维护源、具体资源文件和对应运行清单核对，不维护一份会随代码变化而过期的逐文件迁移清单。旧 rc.7 盘点保留在 Git 历史中，不是当前 Resource Lock。文件校验不提升科学资格，未确认许可的资源不能据此公开再分发。

## 三层开发和验证数据

1. **合成数据：**[协作数据包](../examples/demo/README.md)提供新生成的产品与参考 H5AD、已构建参考、生成脚本及校验值，不读取私有数据。既有私有历史仍留在受控恢复档案，不回传仓库。合成分组和注释不构成真实实验或科学验证。
2. **公开真实数据：**登记来源、条款、版本、hash 和预处理配方后供合作者获取。便捷下载入口与端到端公开样例仍需阶段 2 完成。
3. **内部真实数据：**留在受控环境，由有权限人员使用审核提交执行验收。合作者不能因为获得仓库权限自动下载。

未来资源管理应提供 list、install、register、doctor 等能力，但这些名称只是能力规划，当前不要作为已有命令执行。单机研究环境可以继续使用文件、manifest 和 SQLite；公网元数据数据库是部署实现，不是科学合同。
