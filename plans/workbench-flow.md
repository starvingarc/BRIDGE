# 工作台流程

**状态：** `approved_design; partially_implemented`。2026-10-12 真实接口联调走查后，产品负责人确认的流程。
界面方向见 [BRIDGE 产品设计](bridge-product-design.md)，对象与接口见 [研究内对象](research-objects.md)；
本文记录流程决定及由此提出的接口变更，接口落地后并入合同。

## 1. 入口

- 打开研究默认进入培养箱；新建研究后同样进入培养箱。
- 研究列表与工作台使用同一视觉风格，作为同一个产品的首页。
- 原有会话页保留为历史会话；左栏重整后从顶部研究切换菜单进入（#191）。
- 左栏：研究切换菜单、培养箱 · 比较 · 资料、实验列表、账号（2026-10-14 选定，#191）。报告不放左栏，在实验页与比较页生成和查看，
  文件列在资料中（#189、#192）；当前左栏的“报告”入口为过渡。
- 每个位置都有地址：研究、培养箱、比较、方案图（可带打开的取样点与分析栏）、研究内会话、历史会话。
  刷新或分享链接回到同一位置，浏览器后退在这些位置间移动。地址放在 `#` 之后（如 `#/r/{rid}/flow/{id}/{sample}/qc`；
  旧的 `/tree/{id}` 与 `/results/{id}` 打开对应方案图，`/tree` 打开比较），
  服务端不需要为每个路径返回页面；会话切换只替换地址，不增加后退记录。
- 试剂名称保留用户原文；匹配到小分子库时在旁边显示规范名，不自动改写。

## 2. 对话

- 每一轮分化一条对话，挂在这一轮上，在工作台右侧就地进行，不跳转页面。
- 对话自动带上这一轮的方案版本、样本、映射结果、线索与方案差异作为上下文；用户不需要重复描述实验。
- 研究另有一条总对话，用于跨轮次的问题（例如比较几轮、计划下一轮）。
- Agent 对对象的创建与修改仍以待确认项返回，由用户确认后执行。

接口提议：一轮及研究各绑定一个会话（会话增加 `run_id`，研究总对话以 `research_id` 且无 `run_id` 标识）；
`GET/POST /api/researches/{rid}/runs/{id}/conversation` 返回或创建该会话；发送消息时服务端按绑定对象注入上下文。

## 3. 样本的生命周期

湿实验中，取样后要过一段时间（通常数周）才拿到测序数据。因此登记样本与关联数据分开：

| 状态 | 含义 | 界面 |
|---|---|---|
| 已取样 | 取样当天登记，只有天数、日期与测序类型 | 方案图天数轴下的取样点为虚线，"待测序" |
| 数据已到 | 测序数据上传并关联到样本 | 取样点变实 |
| 映射中 | QC 与标准图谱映射自动运行 | 取样点半实心闪烁；QC 先出现在样本面板 |
| 已完成 / 未完成 | 有结果或有可读的失败原因 | 点开样本面板看映射、QC（含双细胞与细胞周期）与记录 |

- 关联数据时，一个文件可能只含一个样本，也可能含多个样本或时间点；后者由 BRIDGE 按文件中的元数据列提议拆分（哪一组细胞对应哪个样本），用户确认后生效。
- 同一天是否有多个重复、多个捕获，取决于实验者如何提交数据，目前不强制建模；结构上允许一个样本下关联多个数据片段，后续比较按真实的独立单位处理。
- 标准图谱映射在数据关联后自动运行，不进入"等你确认"；"等你确认"只用于探索性分析与耗时较长的计算。
- 映射前要一份数据说明（合同 §7.6 `mapping_input`），在登记或关联数据的同一张表单里用白话问（2026-10-13 产品负责人选定"后端列出矩阵、前端白话选择"）：
  - 原始计数在哪里：选项是文件里实际有的矩阵（主矩阵 X、某某层），由用户明确选择，不按名称或数值预选；可选"不确定，先不映射"，数据照样关联，之后用"补充说明"开始映射。
  - 取样时：移植前／移植后，按取样日期与移植日期预选；移植后或移植前的单核数据会说明暂无对应参考。
  - 细胞来源：预填细胞系（写法不合规时用轮次），用户可改。
  - 说明提交后不能修改。服务端未列出矩阵时退回"主矩阵 X／counts 层／其他层"。
- 映射未能开始时，取样点与样本面板写明当前原因（还差数据说明、没有对应的参考数据、发育树版本已更新、映射任务已满）；
  只有任务已满或上次未完成时提供"重试"。映射进行中，工作台与打开的样本面板每 4 秒刷新一次，结束即停。
- 登记取样可在方案图天数轴上点那一天，也可用顶部"＋ 样本"；关联数据、补充说明、重试映射在样本面板里（2026-10-14 起）。

接口提议：

- `PATCH /api/researches/{rid}/samples/{id}`：`{material_id, scope?, expected_version}` 在取样之后关联数据；
  `scope` 为可选的拆分条件 `{obs_column, value}`，用于一个文件含多个样本的情况。
- Sample 增加 `status: collected | data_attached | mapping | done | failed`（或由服务端从数据与评估推导后返回）。
- 数据关联后自动创建并运行标准 AtlasAssessment（命名、参考、指标为当前版本），不再生成待确认项；
  探索性与耗时任务仍走 ProposedAction。
- 拆分提议：`POST /api/researches/{rid}/materials/{mid}/split-proposal` 返回按元数据列分组的候选（组名、细胞数）；
  确认后逐个关联到样本。

## 4. 前端实施顺序

1. 默认入口、研究列表统一风格与页面地址（不依赖后端）。
2. 样本生命周期界面：取样即登记、待测序状态、之后关联数据（需要上面的 `PATCH` 与 `status`）。
   前端已按上面的提议完成：未关联数据的样本显示为虚线"待测序"，可之后"关联数据"；服务端未注册该接口时提示"后端更新后即可使用"。
   自动映射（#162）上线后，登记与关联都带数据说明，不再有"申请映射"。
3. 每轮对话面板（需要会话绑定接口）。
4. 多样本文件的拆分确认（需要拆分提议接口）。

## 5. 设置与对话模型选择

状态：`implemented; real_provider_walkthrough_pending`。模型相关设置管理服务地址、密钥、模型目录与连接测试；模型和 effort 控件位于对话输入区。前端设计归 Claude，后端配置、权限与任务绑定归 Codex。

每个对话独立保存 `{provider_id, model, effort}`；新对话继承同账号最近一次成功保存的选择；无可继承档位时，采用当前能力元数据声明的默认档位并持久化，整次任务采用同一档位。元数据未声明默认档位时保留 null，不猜测档位，也不注入原先分环节的 high/low/关闭思考策略。已有 null 选择在有效能力到达后首次加载时补齐；已保存档位不随目录默认值改变。PUT null 表示重选当前模型声明的默认档位。旧对话首次加载时冻结当时账号选择，此后互不影响。运行中或已排队任务固定入队时的服务配置、密钥、模型及 effort；修改选择只影响后续新任务。删除模型或能力变更不会静默替换既有对话选择。

### 后端接口

- `GET /api/sessions/{sid}/model-selection`：返回 `selection`、`availability={state, reason}`、`capability={status, supported_levels, default_level}`、`task_configuration`（最近开始执行任务的配置；可能与下一任务选择不同）。普通会话授权适用，管理员不能通过此接口访问他人会话。
- `PUT /api/sessions/{sid}/model-selection`：完整提交 `{provider_id, model, effort}`，校验账号可用模型及 effort，持久化会话并更新账号最近选择；返回同一投影。进行中的任务不阻止保存下一任务选择；归档会话须先恢复。凭据不写入会话。
- `POST /api/models/providers/{provider_id}/capabilities`，空 JSON 对象：从已保存服务获取模型元数据，服务端保存与配置版本绑定的 effort 能力，返回 `{ok, capabilities, checked_at, message}`。任何有权使用共享服务的用户可刷新自己的能力缓存；不能借此修改共享配置或查看密钥。
- `GET /api/models`：保留原有提供商结构，增加各提供商的 `capabilities`，按模型 ID 索引能力。已有目录获取接口可附带同样能力信息，但草稿目录读取不修改持久化配置。
- 能力状态为 `supported`、`unsupported` 或 `unknown`。只接受服务明确声明的已知档位；缺失、格式错误或配置版本失配是 `unknown`，不按模型名猜测。刷新失败不等于不支持，也不使旧结果成为刚验证的结果。无已声明默认档位时仍可使用 `effort: null`，界面须明确未声明；此时请求不指定 effort 或思考开关，由服务自身处理默认行为。
- `409 model_selection_unavailable`：服务、密钥或模型不可用；`409 model_effort_unavailable`：显式 effort 未获当前配置能力支持；`409 model_configuration_changed`：网络读取过程中配置已改变。失败不创建任务、不改最近选择，前端提示重新选择或刷新能力。

### 界面

- 布局照 Claude Code，外观用 BRIDGE 的配色与字体：工作台对话输入框右下角是模型名与思考强度按钮。
  - 点模型名弹出模型菜单（移植自 DeepSeek Harness 的 ModelSelect）：按服务分组、选中项打勾，五个以上模型时出现搜索，底部"管理模型"打开设置的模型页；
    未配置密钥的服务不可选。换模型时档位回到该模型声明的默认值。
  - 点思考强度按钮弹出面板（Radix Popover 与 Slider）：标题写当前档位，两端为"更快 / 更深入"，每个刻度是服务声明的一个档位，声明的默认档位下方标"默认"；
    拖动或方向键切换，松手保存。模型未声明默认档位且未选择时按钮与面板写"服务默认"，不显示滑块位置；档位未确认或不支持调整时不显示该按钮。
  - 修改只影响下一次提问（悬停提示）；保存被拒绝时弹出短提示。
- 按钮先用会话自带的选择，会话存在后读取完整选择（可用性、能力）；首条消息前打开模型菜单会先建立该轮或研究的对话。
- 设置的模型页移植自 DeepSeek Harness 的 models section，控件用 assistant-ui 自带的 Radix（Tabs、AlertDialog、Collapsible、Checkbox）：
  每个服务一张卡片（名称、共享标签、密钥状态点，"刷新能力 / 编辑 / 删除"），下列模型及其声明的 effort（如 "Low · High · Max (default High)"、
  "Effort unconfirmed"）；同一时间只展开一张编辑卡；底部"添加模型提供商"在"第三方模型提供商 / 自定义模型 API"间切换；删除前确认；保存后提示。
  刷新能力失败时写明并保留上次结果的时间；不在设置里选择对话模型。设置窗口暂无深色主题，模型页随窗口保持浅色。
- Effort 及其档位用英文（Effort、Low / Medium / High / Extra high / Max、Faster / Smarter、Default、Provider default），为英文版做准备。
- 工作台左下角的账号行打开设置。旧会话界面不加此控件。

### 实施与验收

1. 配置与能力：扩展现有个人模型存储；服务器校验并限制元数据大小，凭据和地址变更使能力失效。
2. 会话与调度：保存选择、兼容旧会话、固定任务配置；继续复用现有账号与任务授权。
3. 模型请求：默认或显式选择的 effort 统一用于普通对话、工具选择、解释生成/检查/修订以及资料提取/方案结构化，各环节不再自行指定档位。DeepSeek 思考请求移除不兼容的强制工具选择；读取 skill 后的连续调用保留服务要求的 reasoning_content，仅用于该次调用，不公开给用户或写入对话。
4. 合成 HTTP 与真实请求形状验证：两账号、两会话隔离；刷新与重启；新会话继承；任务入队后切换/删除服务仍保留原快照；无效选择不启动任务；抓取发往外部提供商的请求核对模型和 effort。前端联调由对应前端增量承接，未完成时明确标记。

这里不改变科学测量、证据资格、审批或共享规则，也不扩展原生 Anthropic Messages/OpenAI Responses 接口。


旧对话不列入模型选择迁移范围，可在后续经核对的清理步骤中移除；研究、方案、轮次、样本、上传资料和科学结果不因清理对话而删除。本后端增量不执行线上清理或部署。
