# P0-04 Developmental Compatibility

## Purpose

Evaluate a product against a researcher-supplied developmental window. P0-04
keeps stage roles, reference labels, program cards and timepoints in versioned
inputs; it does not encode a fetal-age conversion, preferred state or score.

## Contract

| Field | Value |
|---|---|
| Package version | `0.3.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `no` |
| EnvironmentSpec | `ENV-DEVELOPMENT-PY-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/developmental-compatibility-result/v0.2` |
| Adapter | `bridge.tool_packages.p0_04_developmental_compatibility.adapter:adapter` |

The request is a `ToolRequestV2`; execution returns a `ToolRunV2`. Expression
mode additionally emits a
`bridge://schemas/development-method-bundle/v0.1` artifact.

## Input modes

Both modes require one checksummed JSON object for each of the following roles:

| Role | Schema | Use |
|---|---|---|
| `product_case` | `product-case/v0.1` | Product, assay and biological-unit binding |
| `product_definition_card` | `product-definition-card/v0.1` | Product scope |
| `development_window_spec` | `development-window-spec/v0.1` | Reviewed window and composition channel |
| `development_state_map` | `development-state-map/v0.1` | External state-to-stage and target-related mapping |
| `measurement_spec` | `measurement-spec/v0.2` | Measurement and independence contract |
| `cell_state_evidence_profile` | `cell-state-evidence-profile/v0.3` | Current P0-02 composition and provenance |
| `qc_readiness_profile` | `qc-readiness-profile/v0.2` | P0-01 readiness and selected view |
| `biological_unit_manifest` | `biological-unit-manifest/v0.1` | Analysis and independence units |
| `biological_unit_assignment` | `biological-unit-assignment/v0.1` | Observation-to-unit assignment |
| `annotation_vocabulary` | `annotation-vocabulary/v0.1` | State identity |
| `reference_manifest` | `reference-manifest/v0.1` | Checksummed reference and program assets |

`development_timepoint_series` is optional. Aggregation mode uses no H5AD and
returns the two externally defined stage-composition denominators.

Expression mode adds exactly one normalized, analysis-ready H5AD and one
`development_method_spec`. The H5AD must bind the P0-02 selected view and its
observation identities. The method spec owns reference profiles, reference-label
roles and ranks, program cards, true-time assignments, thresholds and method
selection.

## Executable methods

Catalog aliases select these implementations:

| Alias | Runtime call | Output |
|---|---|---|
| `DEV-PSEUDOBULK-CORR` | sample/preparation pseudobulk with BRIDGE Spearman and cosine reference support | per-unit top label, role, rank, margin and gene coverage |
| `DEV-ORDINAL` | scikit-learn cumulative binary logistic ordinal baseline | per-unit rank distribution and expected rank |
| `DEV-PROGRAM` | decoupler ULM on pseudobulk expression | program activity, p-value and marker coverage |
| `DEV-BOOTSTRAP` | independence-group-preserving NumPy bootstrap | interval for within-window reference support |
| `TIME-PROGRAM` | decoupler activity followed by the declared true-time spline | per-program fitted time trend |
| `TIME-GAM-PY` | statsmodels OLS with a prespecified cubic Patsy B-spline and HC3 covariance | fitted reference-support trend and interval |

The implementation reports package versions and method-level reason codes.
RAPToR, R/Bioconductor composition models, lineage calibration and trajectory/
velocity/OT tools remain conditional catalog entries because their dedicated
input and environment contracts are not part of this package version.

## Output

A run publishes `developmental_compatibility_result.json`. Expression mode also
publishes `development_method_bundle.json`. Both are checksummed and bound to
the immutable input set. Missing evidence remains null/unavailable; one
independence group produces a descriptive bootstrap without a biological
interval. A time spline requires declared unit-to-timepoint mappings, at least
four timepoints and enough independent units.

Every result retains `domain_score=null` and `score_state=unavailable`.
Reference and program results are `shadow` evidence, not biological age,
efficacy, safety or release evidence.

## Calls

```bash
bridge-tool describe P0-04
bridge-tool input-contract P0-04
bridge-tool validate --request examples/requests/p0_04_developmental_compatibility.json
bridge-tool run --request examples/requests/p0_04_developmental_compatibility.json
```

Python callers use `ToolRegistry.load_default()`, `parse_request(payload)`,
`check_eligibility(request)` and `run(request)`.

## Refusal and degradation

Schema, checksum, assay, selected-view, observation identity, biological-unit,
vocabulary, reference or object-binding drift fails before publication. A method
spec and H5AD must be supplied together. Low gene/program coverage, one
independence group or insufficient true timepoints produces typed method-level
`partial`/`not_assessed` evidence rather than zero.

Scientific requirements and validation are documented in the
[task card](../../../../docs/bridge_spec_v0.1/developmental_compatibility_task_card.md)
and [validation record](../../../../docs/validation/p0_04_developmental_compatibility_v0.3.md).
