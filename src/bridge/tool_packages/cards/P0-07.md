# P0-07 Product Comparison & Stability

## Purpose

Compare precomputed product evidence under one explicit comparability contract.
P0-07 checks case/product, metric, MeasurementSpec, unit, denominator, data-view,
timepoint, replicate, confounding and provenance bindings. It does not rerun any
upstream scientific analysis.

## Contract

| Field | Value |
|---|---|
| Package version | `0.2.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `no` |
| EnvironmentSpec | `ENV-P0-CORE-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/product-comparison-stability-profile/v0.1` |
| Adapter | `bridge.tool_packages.p0_07_product_comparison_stability.adapter:adapter` |

## Input interface

P0-07 accepts `ToolRequestV2` containing local, versioned JSON objects with exact
SHA-256 checksums:

| Role | Cardinality | Schema | Meaning |
|---|---:|---|---|
| `comparison_stability_spec` | exactly 1 | `bridge://schemas/comparison-stability-spec/v0.1` | External equality/context/confounding policies and metric contracts |
| `comparison_case_manifest` | exactly 1 | `bridge://schemas/comparison-case-manifest/v0.1` | Baseline/comparator groups and expected bundle membership |
| `product_evidence_bundle` | 2–20 | `bridge://schemas/product-evidence-bundle/v0.1` | One ProductCase/preparation with precomputed metrics and provenance |

Each evidence bundle embeds its ProductCase and ProductDefinitionCard, target
stage, data-view contract, real timepoint, batch/protocol/lab/cell-line metadata,
reference/preprocessing/algorithm versions, metric evidence and optional P0-08
sufficiency reference/state. Metric records preserve unit, denominator, interval,
evidence state, provenance and a permanently unavailable score.

Expression assets, arbitrary parameters, a top-level MeasurementSpec parameter,
or non-zero random seed are refused. Inputs never derive replicate identity from
filenames or paths.

## Calls and example

```bash
bridge-tool describe P0-07
bridge-tool validate --request examples/requests/p0_07_product_comparison_stability.json
bridge-tool run --request examples/requests/p0_07_product_comparison_stability.json
```

Python callers use `ToolRegistry.load_default()`, `parse_request`,
`check_eligibility`, and `run`. Replace all placeholder absolute paths and
checksums in the example with the real local JSON objects.

## Output interface

One checksummed `product_comparison_stability_profile.json` contains:

- `comparison_eligibility`: strict, contextual, reference/OOD, not comparable,
  or not estimable;
- group-level raw metric summaries and observed preparation ranges;
- comparator-minus-baseline delta and neutral numeric direction when legal;
- descriptive preparation/batch stability and explicit confounding factors;
- input hashes, Evidence IDs and stable reason codes;
- `overall_score=null`, `overall_rank=null`, `domain_score=null`, and
  `score_state=unavailable`.

All first-version contrasts are `descriptive_only`; no inferential interval or
significance is computed.

## Missing and refusal behavior

- Missing, unknown or unavailable metric evidence yields a null group value and
  null delta, never zero.
- Alert evidence blocks a numeric contrast.
- Required contract mismatch yields `not_comparable`; configured contextual
  mismatch yields the external policy's contextual/not-comparable state.
- Complete configured protocol/lab/batch/cell-line confounding yields
  `not_estimable`; missing confounder metadata yields `not_comparable`.
- A `reference_ood` group is retained for positioning but is not rankable.
- One preparation reports `single_preparation`; multiple preparations report
  descriptive range only. Technical or cell counts never become independent
  replicates.
- Insufficient or absent P0-08 evidence sufficiency retains traceable raw values
  as shadow but prevents a complete profile.

## Prohibited interpretation

P0-07 never declares a winner, equivalence/non-inferiority, superiority, Pareto
advantage, safety, efficacy, GMP release, best harvest day, or absolute product
ranking. Numeric `increase`/`decrease` describes comparator-minus-baseline only;
it is not biological desirability. Candidate/shadow engineering execution is not
scientific validation.

## Validation

Focused validation covers exact bindings, deterministic reuse, missing evidence,
contract mismatch, contextual comparison, confounding, reference/OOD groups,
single/replicated preparations, checksum failure and V1 refusal. Reproducible
record: `docs/validation/p0_07_product_comparison_stability_v0.2.md`.
