# P0-07 Product Comparison & Stability

## Purpose

Compare precomputed product evidence under an explicit comparability contract.
P0-07 validates case, metric, MeasurementSpec, unit, denominator, data-view,
timepoint, replicate, confounding and provenance bindings before it emits any
numeric comparison. It does not rerun upstream single-cell analysis.

## Contract

| Field | Value |
|---|---|
| Package version | `0.3.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `no` |
| EnvironmentSpec | `ENV-P0-CORE-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/product-comparison-stability-profile/v0.1` |
| Adapter | `bridge.tool_packages.p0_07_product_comparison_stability.adapter:adapter` |

## Input modes

Both modes use `ToolRequestV2` with local, versioned JSON objects and exact
SHA-256 checksums.

| Role | Legacy comparison | Method runtime | Schema | Meaning |
|---|---:|---:|---|---|
| `comparison_stability_spec` | 1 | 1 | `bridge://schemas/comparison-stability-spec/v0.1` | External equality, context, confounding and metric contracts |
| `comparison_case_manifest` | 1 | 1 | `bridge://schemas/comparison-case-manifest/v0.1` | Baseline/comparator groups and expected bundle membership |
| `product_evidence_bundle` | 2–20 | 2–20 | `bridge://schemas/product-evidence-bundle/v0.1` | One ProductCase/preparation with upstream metrics and provenance |
| `comparison_method_spec` | 0 | 1 | `bridge://schemas/comparison-method-spec/v0.1` | Candidate method tasks and externally selected options |
| `comparison_method_input` | 0 | 1 | `bridge://schemas/comparison-method-input/v0.1` | Typed numeric series, semantics, labels, source bundles and evidence refs |

The runtime never derives replicate identity from filenames or paths. Sample-level
series labels must equal the declared ProductCase preparation references.
Probability and matched-feature series carry explicit semantics; all paired
series must share metric, unit and denominator contracts.

Expression assets, arbitrary parameters, a top-level MeasurementSpec parameter
and a non-zero random seed are refused.

## Executed methods

| Method ID | Runtime call | Input semantics | Output |
|---|---|---|---|
| `CMP-EFFECT` | BRIDGE Hedges-g engine | Two independent sample/preparation series | Raw comparator-minus-baseline delta and `hedges_g` |
| `CMP-JS` | `scipy.spatial.distance.jensenshannon` | Two non-negative probability-mass vectors on the same labels | `jensen_shannon_distance` |
| `CMP-CORR` | `scipy.stats.spearmanr` | Two matched-feature pseudobulk profiles | `spearman_rho` |
| `CMP-WASS-1D` | `scipy.stats.wasserstein_distance` | Two ordered scalar distributions, with optional weights | `wasserstein_distance` |
| `STAB-CV` | NumPy mean, standard deviation, median and absolute deviation | One sample/preparation series | Coefficient of variation and, when defined, median absolute-deviation ratio |

These are deterministic descriptive calls. Registered R/Bioconductor, Bayesian,
mixed-model, differential-abundance and integration methods remain independent
benchmark candidates; this package does not claim to execute them.

## Calls and examples

```bash
bridge-tool describe P0-07
bridge-tool input-contract P0-07
bridge-tool validate --request examples/requests/p0_07_product_comparison_stability.json
bridge-tool run --request examples/requests/p0_07_product_comparison_stability.json
bridge-tool validate --request examples/requests/p0_07_comparison_method_runtime.json
bridge-tool run --request examples/requests/p0_07_comparison_method_runtime.json
```

Python callers use `ToolRegistry.load_default()`, `parse_request`,
`check_eligibility` and `run`. Replace all placeholder paths and checksums before
execution.

## Output interface

Every eligible run writes checksummed
`product_comparison_stability_profile.json`, containing:

- comparability and confounding state;
- group-level raw metric summaries and preparation ranges;
- comparator-minus-baseline descriptive deltas when legal;
- exact input bindings, Evidence IDs and stable reason codes;
- `overall_score=null`, `overall_rank=null`, `domain_score=null` and
  `score_state=unavailable`.

Method mode additionally writes checksummed `comparison_method_bundle.json` with
selected method IDs, implementation/package provenance, per-task estimates,
assessment states and typed reasons. Its `evidence_state` is `shadow` and
`domain_score` remains null. `ToolRun.result` stays the backward-compatible
`ProductComparisonStabilityProfile`; the method bundle is a separate artifact.

## Missing, refusal and degradation behavior

- Missing, unknown or unavailable evidence stays null; alert evidence blocks a
  numeric contrast.
- Contract mismatch returns `not_comparable`; complete configured confounding
  returns `not_estimable`.
- Method estimates are `not_assessed` when the comparison is not estimable, a
  profile is constant, pooled variance is zero or a required denominator is
  undefined.
- One preparation remains descriptive. Technical or cell counts never become
  independent replicates.
- Insufficient upstream evidence retains traceable shadow values and prevents a
  complete profile.

## Scientific boundary

P0-07 does not compute p-values, confidence intervals, equivalence,
non-inferiority, superiority, Pareto advantage, product ranking, safety, efficacy
or release decisions. Numeric direction and distance have no intrinsic biological
good/bad meaning. Engineering execution remains `candidate/shadow` and is not
scientific validation.
