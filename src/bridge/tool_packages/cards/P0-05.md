# P0-05 Off-target Control

## Purpose

Account for a declared primary denominator under externally supplied roles and
uncertainty rules. The package keeps its original aggregation interface and an explicit
method-runtime interface for descriptive intervals, independent-unit bootstrap,
rare-state spike-in/design calculations and multi-source OOD coordination, plus
an opt-in normalized measurement projection.

## Contract

| Field | Value |
|---|---|
| Package version | `0.5.2` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `no` |

| Input envelope | `bridge://schemas/tool-request/v0.2` |

| Result schema | `bridge://schemas/off-target-control-profile/v0.2` |

Profile v0.1 remains packaged for legacy loading.

Use `ToolRequestV2` through the Python SDK `validate_request` and `run_tool`,
or the existing CLI:

```bash

bridge-tool run --request /absolute/path/to/p0_05_request.json
```

The committed example contains placeholder paths and checksums:
`examples/requests/p0_05_off_target_control.json`.

## Structured inputs

P0-05 accepts two exact input modes. `legacy_aggregation` preserves the original
six-object contract. `method_runtime` adds four objects and requires the richer
P0-02 V3 profile so analysis units and reconciliation counts remain auditable.

| Role | Modes | Schema | Required content |
|---|---|---|---|
| `product_case` | both | `bridge://schemas/product-case/v0.1` | case, product, assay and MeasurementSpec binding |
| `product_definition_card` | both | `bridge://schemas/product-definition-card/v0.1` | supported assay and exact StateRoleMap reference |
| `state_role_map` | both | `bridge://schemas/state-role-map/v0.1` | caller-owned state-to-role assignments |
| `off_target_assessment_spec` | both | `bridge://schemas/off-target-assessment-spec/v0.1` | denominator, unknown allowlist and rare-state acceptance limits |
| `cell_state_evidence_profile` | both | V2 in legacy; `bridge://schemas/cell-state-evidence-profile/v0.3` in method mode | upstream identity, composition and selected data view |
| `off_target_evidence_bundle` | both | `bridge://schemas/off-target-evidence-bundle/v0.1` | state/unknown counts and supplied calibration records |
| `biological_unit_manifest` | method and any projected run | `bridge://schemas/biological-unit-manifest/v0.1` | immutable P0-01-declared analysis-unit and independence-group mapping |
| `biological_unit_attestation_receipt` | method | `bridge://schemas/biological-unit-attestation-receipt/v0.1` | caller/data-owner assertion for `analysis_execution`, bound to the exact manifest, assignment, DataView, observation set and attestation trace |
| `off_target_method_spec` | method | `bridge://schemas/off-target-method-spec/v0.1` | selected methods, confidence level, bootstrap size, planning targets, OOD channel lineage and ordered rules |
| `off_target_method_input` | method | `bridge://schemas/off-target-method-input/v0.1` | unit-level soft/hard composition, spike-in trials and OOD channel states |
| `measurement_spec` | optional in both | `bridge://schemas/measurement-spec/v0.2` | independent P0-05 domain contract; assay, product applicability, tool authorization, metric names and biological units are checked |

Every object is bound by Schema URI, object version, absolute regular-file path
and SHA-256. Method mode also checks the exact ProductCase, P0-02 V3 profile,
evidence bundle, selected DataView, biological-unit manifest, analysis-unit set,
independence groups and aggregate counts. All four method-specific objects must
be present together.

The method selector currently executes:

- `COMP-EXACT`: descriptive Clopper-Pearson cell-count intervals;
- `COMP-HARD-SENS`: hard-versus-soft role-composition sensitivity;
- `COMP-HBOOT`: bootstrap over declared independence groups;
- `RARE-EXACT`: descriptive rare-state count intervals;
- `RARE-SPIKEIN`: empirical detection hit-rate curves and a candidate detection limit;
- `RARE-BINOMIAL-AT-LEAST-ONE`: single-state, at-least-one-cell binomial planning;
- `OOD-DISAGREE`: disagreement across distinct source families;
- `OOD-ENSEMBLE`: ordered coordination rules supplied in the method spec.

P0-05 refuses expression assets, arbitrary parameters, the legacy top-level
`measurement_spec_ref`, V1 requests, unmapped states, undeclared unknown reasons,
inactive specs, partial method inputs and any lineage/checksum mismatch. Method mode
requires the immutable P0-01 `declared` manifest plus one confirmed
`analysis_execution` attestation receipt. It records a caller/data-owner assertion
and binds the exact manifest, assignment, selected DataView, observation-set digest,
unit contract, attestor, timestamp and immutable conversation/workflow attestation
reference/checksum; a `reviewed` or `frozen` manifest cannot substitute for it.
The runtime validates only receipt structure and these content bindings. It does not
authenticate the attestor or establish biological truth, independent review,
publication approval or product release authority. The deployment layer maps an
authenticated conversation record to `attestation_ref` and `attestation_sha256`.
A structured MeasurementSpec fails closed unless one checksummed
BiologicalUnitManifest is present, its analysis, independence and observation units
match the run, `tool_refs` contains `P0-05`, and
`raw_metric_definition.metric_names` names exactly the three supported projections.
The P0-05 MeasurementSpec is independent of the upstream P0-02 MeasurementSpec
recorded by ProductCase.

## Deterministic output

Every successful run writes `off_target_control_profile.json` and returns the
same object in `ToolRunV2.result`. Method mode atomically adds a checksummed
`off_target_method_bundle.json` governed by
`bridge://schemas/off-target-method-bundle/v0.1`.

P0-05 v0.5.2 always returns profile v0.2. Without a structured MeasurementSpec it
preserves all domain records, sets `measurement_projection_state=not_requested`
and binds no measurements. With an authorized MeasurementSpec it sets the state
to `available` and atomically adds one checksummed `MeasurementResultV2` artifact
per source record.

The primary profile contains:

- exact upstream refs and hashes and one primary denominator;
- soft mass, observed count and fraction for the four generic product roles;
- unknown composition split only by caller-declared reason IDs;
- rare-state detection records evaluated only against external limits;
- explicit limitation reason codes;
- `evidence_state=shadow`, `score_state=unavailable` and
  `domain_score=null`.
The method bundle records exact method/input/manifest hashes, analysis units,
independence groups, package versions and one execution state per selector. It
contains descriptive count intervals, group-bootstrap intervals, hard/soft
sensitivity, spike-in detection hit-rate curves with independent-group counts, candidate detection
limits, single-state binomial planning records and OOD coordination results. A random seed is part of the run
fingerprint whenever stochastic bootstrap is selected.

Every successful run also publishes one typed visualization data object, exact
TSV fallbacks and deterministic SVG, PNG and PDF renders for:

- declared product-role and identity-unknown accounting;
- rare-state observations with separately named detection boundaries;
- supplied OOD channel states grouped by their declared source family.

Cell-count intervals do not represent replicate-level uncertainty. The planning
record is only a single-state at-least-one-cell binomial calculation, not
SCOPIT; it retains independent-random-sampling and perfect-detection assumptions.
OOD channel family, upstream-result checksum, method and reference identity are
fixed by the checksummed MethodSpec. An internally conflicting family yields
`not_assessed`.

Incomplete composition withholds fractions and returns `not_assessed`.
A zero role or unknown observation returns `cannot_exclude`, never absence.
A calibrated zero rare-state observation may return
`not_detected_above_lod` with its supplied upper bound, while missing or
insufficient calibration returns `cannot_exclude` or `not_assessed`.

Projection preserves the complete source records in profile v0.2 and uses this
explicit evidence-state mapping:

- role `available` to `inferred`, and `not_assessed` to `unavailable`;
- unknown coverage `complete` or `partial` to `unknown(identity)`, and
  `not_assessed` to `unavailable`;
- rare `detected` to `inferred`, `not_detected_above_lod` to `negative`,
  `cannot_exclude` to `unknown(measurement)`, and `not_assessed` to `unavailable`.

States for which MeasurementResultV2 forbids values carry nulls, never fabricated
zeros. Every projected result keeps `domain_score=null` and
`score_state=unavailable`; no projection adds a threshold or safety interpretation.
The package does not rerun single-cell analysis.
Figures remain candidate explanations of the structured records.

## Biology and release boundary

No biological state, role assignment, evidence class, unknown-reason vocabulary
or numerical threshold is embedded in the implementation. Those decisions
remain versioned external inputs so later biological review can revise them
without code changes.

Registered methods map to the eight executable selectors above plus the retained
role-aware aggregator. P0-05 coordinates supplied OOD channel states; it does
not train a deep OOD classifier. It estimates an engineering-candidate
detection limit only from supplied spike-in trials and externally supplied
acceptance rules. No result establishes biological truth, clinical safety,
efficacy, potency, GMP release or an absolute product ranking.

## Validation

Synthetic contract tests cover both input modes, eight method selectors,
analysis-unit and attestation-receipt bindings, count and bootstrap intervals,
hard/soft sensitivity, independent-group spike-in calibration, single-state
binomial planning, checksummed OOD coordination,
missing/zero semantics, checksum drift, deterministic reuse and output
tampering, v0.1 compatibility and opt-in v0.2 measurement projection.
