# P0-05 Off-target Control

## Purpose

Aggregate precomputed whole-product cell-state evidence by externally defined
product roles, unknown reasons and rare-state calibration limits.

## Contract

| Field | Value |
|---|---|
| Package version | `0.2.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `no` |
| EnvironmentSpec | `ENV-P0-CORE-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/off-target-control-profile/v0.1` |
| Adapter | `bridge.tool_packages.p0_05_off_target_control.adapter:adapter` |

Use `ToolRequestV2` through the Python SDK `validate_request` and `run_tool`,
or the existing CLI:

```bash
bridge-tool validate --request /absolute/path/to/p0_05_request.json
bridge-tool run --request /absolute/path/to/p0_05_request.json
```

The committed example contains placeholder paths and checksums:
`examples/requests/p0_05_off_target_control.json`.

## Structured inputs

Exactly six immutable `application/json` objects are required.

| Role | Schema | Required content |
|---|---|---|
| `product_case` | `bridge://schemas/product-case/v0.1` | case, ProductDefinition, assay and MeasurementSpec binding |
| `product_definition_card` | `bridge://schemas/product-definition-card/v0.1` | supported assay and exact StateRoleMap reference |
| `state_role_map` | `bridge://schemas/state-role-map/v0.1` | caller-owned state-to-role assignments and evidence interpretation |
| `off_target_assessment_spec` | `bridge://schemas/off-target-assessment-spec/v0.1` | map checksum, denominator, allowed unknown reasons and rare-state limits |
| `cell_state_evidence_profile` | `bridge://schemas/cell-state-evidence-profile/v0.2` | stable upstream profile identity, assay, MeasurementSpec and observation count |
| `off_target_evidence_bundle` | `bridge://schemas/off-target-evidence-bundle/v0.1` | precomputed state/unknown observations, denominator and calibration records |

Every object is bound by Schema URI, object version, absolute regular-file path
and SHA-256. The bundle additionally binds the ProductCase,
ProductDefinitionCard and Cell-State profile by reference and checksum; the
assessment spec binds the exact StateRoleMap checksum.

P0-05 refuses expression assets, arbitrary parameters, top-level
MeasurementSpecs, V1 requests, unmapped states, undeclared unknown reasons,
inactive specs and any lineage/checksum mismatch.

## Deterministic output

A successful run writes one checksummed
`off_target_control_profile.json` and returns the same object in
`ToolRunV2.result`. It contains:

- exact upstream refs and hashes and one primary denominator;
- soft mass, observed count and fraction for the four generic product roles;
- unknown composition split only by caller-declared reason IDs;
- rare-state detection records evaluated only against external limits;
- explicit limitation reason codes;
- `evidence_state=shadow`, `score_state=unavailable` and
  `domain_score=null`.

Incomplete composition withholds fractions and returns `not_assessed`.
A zero role or unknown observation returns `cannot_exclude`, never absence.
A calibrated zero rare-state observation may return
`not_detected_above_lod` with its supplied upper bound, while missing or
insufficient calibration returns `cannot_exclude` or `not_assessed`.

The package emits no MeasurementResult or visualization and does not rerun
single-cell analysis.

## Biology and release boundary

No biological state, role assignment, evidence class, unknown-reason vocabulary
or numerical threshold is embedded in the implementation. Those decisions
remain versioned external inputs so later biological review can revise them
without code changes.

The registered method
`METHOD-BRIDGE-ROLE-AWARE-SOFT-COMPOSITION` describes deterministic
aggregation only. It is not an OOD classifier, calibration fitter or safety
model. The result does not establish biological truth, clinical safety,
efficacy, potency, GMP release or an absolute product ranking.

## Validation

Synthetic contract tests cover external role reassignment, complete and partial
denominators, unknown-reason refusal, calibrated detection, calibrated zero,
missing/insufficient calibration, missing rare observations, cross-object
bindings, checksum drift, V1 refusal, deterministic reuse and output tampering.
