# P0-03 Target Identity & Regional Fidelity

## Purpose

Bind a P0-02 V3 composition to one ProductCase and external role definitions,
then publish three denominator-explicit candidate ratios. P0-03 aggregates
precomputed counts only; it does not read expression matrices or infer biology.

## Contract

| Field | Value |
|---|---|
| Package version | `0.2.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `no` |
| EnvironmentSpec | `ENV-P0-CORE-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/target-regional-evidence-result/v0.1` |
| Adapter | `bridge.tool_packages.p0_03_target_regional.adapter:adapter` |

Construct a `ToolRequestV2`, then use
`ToolRegistry.load_default().check_eligibility(request)` and `.run(request)`
from Python, or:

```bash
bridge-tool validate --request /absolute/path/to/p0_03_request.json
bridge-tool run --request /absolute/path/to/p0_03_request.json
```

The documentation-only request is
`examples/requests/p0_03_target_regional_evidence.json`. Replace every path and
SHA-256 before use.

## Binding and calculation

Eligibility fails closed unless ProductCase, ProductDefinitionCard,
MeasurementSpec, selected DataView, QC profile, biological-unit manifest and
assignment all describe the same case and lineage. The adapter also requires
the P0-02 V3 MeasurementSpec, AnnotationVocabulary, ReferenceManifest and QC
SHA-256 values to equal the supplied object checksums. Vocabulary IDs/versions,
reference IDs/versions, label levels, source IDs and P0-03 QC eligibility must
agree.

All biological choices are external. `StateRoleMap` owns state roles;
`TargetRegionalAssessmentSpec` owns requested views/sources/levels and the role
sets used for every numerator and denominator. Python contains no state names,
genes, markers, thresholds or product-specific target definitions.

For every requested channel the executor emits only these ratio types:

1. `target_identity_fraction`: configured lineage-role count / selected DataView;
2. `regional_fidelity_fraction`: configured regional-role count / configured
   target-related count;
3. `whole_product_target_region_fraction`: configured regional-role count /
   selected DataView.

An `unknown` or `ood` reconciliation record makes the channel `not_assessed` and
all three values null. Missing or unresolved mappings are also not converted to
numbers. A zero target-related denominator leaves only
`regional_fidelity_fraction` `unavailable` with null value, numerator and
denominator; it is never reported as zero. Typed reason codes preserve each
refusal or degraded-state cause.

## Outputs

One atomic run directory contains:

- one checksummed `TargetRegionalEvidenceResult` JSON;
- one independent checksummed `MeasurementResultV2` JSON for each normalized
  metric and requested channel.

The result binds all eleven input checksums, all object references, channel
states and each metric artifact checksum. ToolRun also exposes the three metric
projections for Agent clients. Repeating the same inputs reuses identical bytes;
changed or extra files under the same deterministic run ID fail closed.

`complete` means every requested channel has three ratios. `partial` means at
least one channel or the regional denominator is unavailable. `not_assessed`
means no channel has a numeric result. Numeric candidate outputs remain
`shadow`; otherwise score state is `unavailable`. `domain_score` is always
`null`, spatial projection remains `not_assessed`, and no visualization is
emitted.

## Interpretation boundary

The package proves deterministic contract binding and arithmetic only.
`candidate`, `complete` and `shadow` do not establish biological truth,
reference suitability, target identity, regional fidelity, potency, efficacy,
safety, clinical benefit, GMP release or product ranking. Scientific use still
requires reviewed external objects and independent validation.
