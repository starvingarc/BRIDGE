# P0-03 Target Identity & Regional Fidelity

## Purpose

Bind a P0-02 V3 composition to one ProductCase and external role definitions.
The default mode publishes three denominator-explicit ratios from precomputed
composition. An optional expression mode also executes configured target and
regional evidence methods on the exact QC-selected H5AD view.

## Contract

| Field | Value |
|---|---|
| Package version | `0.3.0` |

Construct a `ToolRequestV2`, then use
`ToolRegistry.load_default().check_eligibility(request)` and `.run(request)`

```bash
bridge-tool validate --request /absolute/path/to/p0_03_request.json
bridge-tool run --request /absolute/path/to/p0_03_request.json
```

Start with `examples/requests/p0_03_target_regional_evidence.json` for
aggregation or `examples/requests/p0_03_target_regional_expression.json` for
expression methods. Replace every path and SHA-256 before use.

Both modes require eleven immutable `application/json` objects. Each
`StructuredInputRef` carries a role, Schema URI, object version, absolute
regular-file path and SHA-256.

| `product_case` | `bridge://schemas/product-case/v0.1` | `0.1.0` | Product, source unit, MeasurementSpec, data-view and lineage scope |
| `product_definition_card` | `bridge://schemas/product-definition-card/v0.1` | `0.1.0` | Assay scope and exact StateRoleMap reference |
| `state_role_map` | `bridge://schemas/state-role-map/v0.1` | `0.1.0` | Shared P0-05-owned state-to-product-role contract, consumed without redefinition |
| `target_regional_assessment_spec` | `bridge://schemas/target-regional-assessment-spec/v0.1` | `0.1.0` | Exact StateRoleMap checksum, requested channels, target product roles and regional state-ID sets |
| `measurement_spec` | `bridge://schemas/measurement-spec/v0.2` | payload `version` | Units, applicable context and provenance contract |
| `cell_state_evidence_profile` | `bridge://schemas/cell-state-evidence-profile/v0.3` | `0.3.0` | Typed P0-02 composition and MeasurementSpec/vocabulary/reference/QC checksums |
| `qc_readiness_profile` | `bridge://schemas/qc-readiness-profile/v0.2` | `0.2.0` | P0-01 readiness, module eligibility and selected DataView |
| `biological_unit_manifest` | `bridge://schemas/biological-unit-manifest/v0.1` | `0.1.0` | Observation, analysis-unit and independence-group lineage |

| `target_regional_method_spec` | `bridge://schemas/target-regional-method-spec/v0.1` | `0.1.0` | Optional method selection, separate target/regional references, program cards, coverage minima and bootstrap settings |

Aggregation mode supplies no expression asset or method spec and requires
`random_seed=0`. Expression mode adds exactly one checksummed
`analysis_ready` scRNA/snRNA H5AD plus exactly one
`target_regional_method_spec`. The asset must identify its selected DataView
and parent asset checksum; both are matched to P0-01/P0-02 lineage. Top-level
`measurement_spec_ref` and arbitrary `parameters` are refused.

## Binding and calculation

Eligibility fails closed unless ProductCase, ProductDefinitionCard,
MeasurementSpec, selected DataView, QC profile, biological-unit manifest and
assignment all describe the same case and lineage. The adapter also requires
the P0-02 V3 MeasurementSpec, AnnotationVocabulary, ReferenceManifest and QC
SHA-256 values to equal the supplied object checksums. Vocabulary IDs/versions,
reference IDs/versions, label levels, source IDs, shared StateRoleMap
ref/checksum and P0-03 QC eligibility must agree.

All biological choices are external. The shared `StateRoleMap` owns product
roles. `TargetRegionalAssessmentSpec` owns requested views/sources/levels, the
product roles used for target identity and the state-ID sets used for regional
membership. Python contains no state names, genes, markers, thresholds or
product-specific target definitions.

### Expression methods

The short selectors below are aliases from the P0-03 master catalog. The package
spec registers their canonical `METHOD-*` IDs in the knowledge snapshot.

The optional mode executes only the method IDs selected in the checksummed method
spec:

| Method ID | Runtime action | Output |
|---|---|---|
| `TRG-PBCORR` | sample-pseudobulk Spearman/cosine against target references | top label, support, runner-up margin and shared-gene count |
| `REG-PBCORR` | the same transparent calculation against a separate regional reference set | regional label support and margin |
| `TRG-NNLS` | SciPy non-negative least squares over target reference centroids, normalized to a simplex | continuous state weights and residual norm |
| `TRG-DECOUPLER` | decoupler ULM on explicit signed target program cards | activity, p-value and observed marker coverage |
| `REG-DECOUPLER` | decoupler ULM on explicit signed regional program cards | regional program activity and coverage |
| `TRG-BOOTSTRAP` | nonparametric resampling over P0-01 independence groups | interval, or `descriptive_only` for one independent group |
| `REG-CROSSREF` | compare regional labels/support across reference profiles | agreement and support range |
| `REG-MODALITY` | compare regional evidence across scRNA/snRNA references | modality agreement or typed non-assessment |

Pseudobulk units and bootstrap independence groups come from the supplied
`BiologicalUnitAssignmentArtifact`; H5AD sample columns cannot silently redefine
them. Reference matrices, metadata and marker-program files are resolved through
the supplied `ReferenceManifest` and verified by checksum before use.

CellTypist, scANVI, SingleR, scmap, Symphony and scConform remain P0-02 benchmark
adapters whose evidence can enter through the P0-02 profile. Spatial methods in
the catalog remain conditional and are not invoked by P0-03 v0.3.0.

For every requested channel the executor emits only these ratio types:

1. `target_identity_fraction`: configured product-role count / selected DataView;
2. `regional_fidelity_fraction`: configured regional numerator-state count /
   configured regional denominator-state count;
3. `whole_product_target_region_fraction`: configured regional state count /
   selected DataView.

An `unknown` or `ood` reconciliation record makes the channel `not_assessed` and
all three values null. Missing or unresolved mappings are also not converted to
numbers. A zero target-related denominator leaves only
`regional_fidelity_fraction` `unavailable` with null value, numerator and
denominator; it is never reported as zero. Typed reason codes preserve each
refusal or degraded-state cause.

## Outputs

One atomic run directory contains:

- one checksummed `TargetRegionalEvidenceResult` JSON;
- one independent checksummed `MeasurementResultV2` JSON for each normalized
  metric and requested channel;
- in expression mode, one checksummed `TargetRegionalMethodBundle` containing
  method-level evidence, software versions, biological units and provenance.

The result binds the eleven core inputs and, when present, the expression asset
and method spec. ToolRun exposes the ratio projections and published artifact
checksums. Repeating the same inputs reuses identical bytes; changed inputs or
conflicting files under the same deterministic run ID fail closed.

`complete` means every requested ratio channel is complete. Expression-mode
execution is `partial` when a selected method returns partial or
`not_assessed` evidence, including the expected one-independent-unit bootstrap
case. Numeric candidate outputs remain `shadow`; otherwise score state is
`unavailable`. `domain_score` is always `null`, spatial projection remains
`not_assessed`, and no visualization is emitted.

## Interpretation boundary

The package proves deterministic contract binding and execution of the listed methods.
`candidate`, `complete` and `shadow` do not establish biological truth,
reference suitability, target identity, regional fidelity, potency, efficacy,
safety, clinical benefit, GMP release or product ranking. Scientific use still
requires reviewed external objects and independent validation.

`docs/bridge_spec_v0.1/target_regional_identity_task_card.md`.
