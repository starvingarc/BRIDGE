# P0-12 Optional Graft Assessment

## Purpose

Represent optional post-transplant evidence as an independent, deterministic
candidate result. P0-12 aggregates only precomputed records; it does not run
single-cell analysis, infer preparation linkage, or change pretransplant
evidence.

## Contract

| Field | Value |
|---|---|
| Package version | `0.2.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `yes` |
| EnvironmentSpec | `ENV-P0-CORE-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/graft-assessment-result/v0.1` |
| Adapter | `bridge.tool_packages.p0_12_graft_assessment.adapter:adapter` |

The SDK accepts `ToolRequestV2` through
`ToolRegistry.load_default().check_eligibility(request)` and `.run(request)`.
The CLI equivalents are:

```bash
bridge-tool validate --request /absolute/path/to/p0_12_request.json
bridge-tool run --request /absolute/path/to/p0_12_request.json
```

The committed no-graft example is
`examples/requests/p0_12_graft_assessment.json`.

## Input modes

### Graft not provided

An empty `object_inputs` list is valid. The deterministic result has
`state=not_provided`, `analysis_mode=unavailable`,
`evidence_state=unavailable`, and
`pretransplant_evidence_effect=none`.

### Graft provided

Exactly three immutable `application/json` objects are required. Each
`StructuredInputRef` carries an absolute regular-file path, lowercase SHA-256
checksum, exact Schema URI and matching `object_version=0.1.0`.

| Role | Schema | Required content |
|---|---|---|
| `graft_case` | `bridge://schemas/graft-case/v0.1` | Case, assay/specimen, optional animal/timepoint/replicate, explicit preparation linkage, confounders and provenance |
| `assessment_spec` | `bridge://schemas/graft-assessment-spec/v0.1` | Versioned role rules, allowed metric IDs, allowed states, state classes, registered method IDs and provenance |
| `evidence_bundle` | `bridge://schemas/graft-evidence-bundle/v0.1` | Precomputed evidence records bound to the exact case and assessment spec |

The external `GraftAssessmentSpec`, not Python code, owns all evidence roles,
metric IDs, states and their structural classes. In the first candidate,
composition, reference, maturation and unknown are example roles rather than
hard-coded biology.

P0-12 refuses expression assets, top-level MeasurementSpecs, arbitrary
parameters, wrong roles or versions, checksum drift, invalid JSON, cross-object
reference drift, unregistered method sets, and evidence records outside the
external spec.

## Output

A successful call returns one `GraftAssessmentResult` plus two checksummed JSON
artifacts:

- `graft_assessment_result.json`;
- `artifact_manifest.json`.

For provided graft evidence, the result remains
`state=candidate`, `analysis_mode=descriptive_only` and
`evidence_state=shadow`. It contains exact source bindings, deterministic
per-role counts and state-class counts, missing metadata, declared confounders,
missing required roles and an optional explicit preparation linkage record.
`domain_score=null`, `score_state=unavailable`, and
`pretransplant_evidence_effect=none` are invariant.

Missing animal, post-transplant timepoint or biological replicate metadata adds
`graft_metadata_incomplete`. Missing explicit preparation linkage produces
`provided_unlinked`; filenames, directories and labels are never used to infer
it. Declared confounding and absent required roles remain visible reason codes
and cannot promote the result beyond descriptive shadow evidence.

## Refusal and determinism

Contract failures return a failed `ToolRunV2` with typed reason codes and no
result or artifacts. Representative codes include
`exactly_one_graft_case_required`, `object_input_schema_mismatch`,
`structured_input_checksum_mismatch`, `graft_case_binding_mismatch`,
`assessment_spec_binding_mismatch`,
`graft_evidence_contract_mismatch`,
`structured_input_modified_during_run`, and
`existing_run_bundle_hash_mismatch`.

The run fingerprint excludes request IDs, output paths and filesystem metadata.
Repeated identical inputs reuse byte-identical output; changed bytes under an
existing run ID fail closed.

## Scientific boundary

The registered methods are the GraftCase Validator and soft-composition
candidate already present in the knowledge snapshot. P0-12 does not recompute
scRNA-seq/snRNA-seq, validate the upstream biological method, infer efficacy,
safety, potency, maturation truth, clinical outcome, GMP release or product
rank. Graft evidence is independent and never backfills pretransplant domains.

No visualization is generated in this first executable candidate.
