# P0-12 Optional Graft Assessment

## Purpose

Run an optional, independent graft assessment without changing pre-transplant
product evidence. P0-12 accepts no graft, precomputed graft evidence, or a
checksummed H5AD plus external analysis contracts.

## Contract

| Field | Value |
|---|---|
| Package version | `0.3.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `yes` |
| EnvironmentSpec | `ENV-P0-CORE-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/graft-assessment-run-result/v0.1` |
| Adapter | `bridge.tool_packages.p0_12_graft_assessment.adapter:adapter` |

The CLI and SDK use the same adapter:

```bash
bridge-tool describe P0-12
bridge-tool input-contract P0-12
bridge-tool validate --request /absolute/path/to/request.json
bridge-tool run --request /absolute/path/to/request.json
```

Python callers use
`ToolRegistry.load_default().check_eligibility(request)` and `.run(request)`.
The Agent-facing envelope for all three modes is `ToolRequestV2`.

## Input modes

Each JSON object is referenced through a `StructuredInputRef` with an absolute
regular-file path, lowercase SHA-256, exact Schema URI and
`object_version=0.1.0`.

### `not_provided`

`object_inputs=[]` returns a deterministic `GraftAssessmentResult` with
`state=not_provided`, `analysis_mode=unavailable` and
`pretransplant_evidence_effect=none`.

### `graft_assessment`

This compatibility mode aggregates three precomputed objects:

| Role | Schema |
|---|---|
| `graft_case` | `bridge://schemas/graft-case/v0.1` |
| `assessment_spec` | `bridge://schemas/graft-assessment-spec/v0.1` |
| `evidence_bundle` | `bridge://schemas/graft-evidence-bundle/v0.1` |

The external assessment spec owns evidence roles, metric IDs, states and state
classes. The result is descriptive; P0-12 does not reinterpret upstream values.

### `expression_analysis`

This mode reads one H5AD through a checksummed asset manifest and requires five
objects:

| Role | Schema | Required content |
|---|---|---|
| `graft_case` | `bridge://schemas/graft-case/v0.1` | Case, assay, optional graft metadata and provenance |
| `graft_expression_asset` | `bridge://schemas/graft-expression-asset/v0.1` | H5AD path/checksum, organism, gene namespace, assay, matrix/value semantics, expression layer, sample/graft fields and state-probability columns |
| `graft_expression_analysis_spec` | `bridge://schemas/graft-expression-analysis-spec/v0.1` | Method set, minimum coverage, probability tolerance and file-size limit (hard ceiling 2 GB) |
| `graft_reference_panel` | `bridge://schemas/graft-reference-panel/v0.1` | External profiles with source family, organism, gene namespace, assay and value semantics |
| `graft_marker_program_collection` | `bridge://schemas/graft-marker-program-collection/v0.1` | External gene programs with source family, organism, gene namespace and value semantics |

No state names, reference profiles, marker programs, biological thresholds or
release rules are hard-coded in the adapter.

## Executed calculations and registered methods

The expression path executes:

- AnnData and Scanpy H5AD reading;
- the shared P0-01 expression-object validator for non-empty matrices, unique
  IDs, finite nonnegative values and integer raw counts; this is structural
  validation, and the result records `qc_state=not_reassessed`;
- GraftCase and external-contract binding checks;
- Scanpy `normalize_total` and `log1p` when the declared layer contains raw
  counts;
- pooled descriptive soft composition from external per-row probability
  columns, with denominator `all_uploaded_rows` and no confidence interval;
- sample-pseudobulk Spearman correlation against external reference profiles;
- mean expression and gene coverage for external marker programs.

The selected registered method IDs cover binding, composition, reference
correlation and Scanpy/AnnData calls. The shared matrix validator and external
marker-program mean are implementation calculations, not independent scientific
methods. The implementation uses AnnData, Scanpy, NumPy, pandas and SciPy. It
does not invoke a classifier, train a model, infer cell states, fetch a reference
or reassess graft QC.

## Output

The result Schema is a union:

- `GraftAssessmentResult` for no-input or precomputed modes;
- `GraftExpressionAnalysisResult` for H5AD analysis.

Expression analysis reports cell/gene/sample/graft counts, unassigned
probability fraction, descriptive soft composition over all uploaded rows,
sample-pseudobulk reference support, external marker-program means, reference
and marker source families, `analysis_value_semantics=log1p_cp10k`,
`qc_state=not_reassessed`, exact source bindings,
runtime versions and selected method IDs. It publishes
`graft_expression_analysis_result.json` and `artifact_manifest.json`.

Every provided result remains `candidate/shadow`.
`domain_score=null`, `score_state=unavailable`,
`pretransplant_evidence_effect=none` and no visualization are invariant.

## Refusal and degradation

Envelope, Schema, checksum, object-version, source-family context, organism,
gene-namespace, assay, value-semantics, cross-object and method-set drift fail
before publication. H5AD failures include missing or changing files, missing
declared layers/metadata, unsafe sample/graft labels, duplicate identifiers,
non-finite values, invalid raw counts and invalid probability matrices.

Insufficient reference or marker coverage is recorded as unavailable evidence
with a reason code. Composition remains descriptive for any sample count; no
confidence interval is attempted. Missing graft IDs or optional case metadata
remain visible reason codes; they are not inferred from filenames or folders.

Repeated identical inputs reuse byte-identical output. Input mutation during a
run or changed bytes under an existing run ID fail closed.

## Scientific boundary

Engineering validation establishes that the declared files are read and the
registered deterministic calculations run through the public interface. It does
not establish biological annotation accuracy, graft efficacy, safety, potency,
maturation truth, clinical outcome, product rank or release suitability. Graft
evidence never backfills pre-transplant domains.
