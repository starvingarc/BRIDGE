# P0-11 Public-safe Export

## Purpose

Rebuild a P0-10-eligible structured report as a minimal public JSON candidate.
The package projects only approved fields, applies approved public case aliases,
checks deterministic leak canaries and binds a later confirmation to the exact
candidate hash. It never edits the source report or uploads an artifact.

## Contract

| Field | Value |
|---|---|
| Package version | `0.2.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Optional | `no` |
| EnvironmentSpec | `ENV-EVIDENCE-v0.1` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/public-export-result/v0.1` |
| Adapter | `bridge.tool_packages.p0_11_public_safe_export.adapter:adapter` |

The SDK entry points are `ToolRegistry.load_default().check_eligibility(request)`
and `.run(request)` with `ToolRequestV2`. The CLI equivalents are:

```bash
bridge-tool validate --request /absolute/path/to/p0_11_request.json
bridge-tool run --request /absolute/path/to/p0_11_request.json
```

The committed example uses placeholder absolute paths and checksums:
`examples/requests/p0_11_public_safe_export.json`.

## Structured inputs

Exactly four immutable `application/json` objects are required. Each
`StructuredInputRef` carries an absolute regular-file path, lowercase SHA-256
checksum, exact Schema URI and object version `0.1.0`.

| Role | Schema | Required binding |
|---|---|---|
| `report_draft` | `bridge://schemas/report-draft/v0.1` | Original public-candidate `ReportDraft` |
| `claim_verification_result` | `bridge://schemas/claim-verification-result/v0.1` | Eligible receipt with matching report ref, content hash and audience |
| `public_export_policy` | `bridge://schemas/public-export-policy-spec/v0.1` | Active channel, field allowlist, public aliases and statement allowlist |
| `public_export_request` | `bridge://schemas/public-export-request/v0.1` | Matching report/policy refs, target channel and optional confirmation hash |

Expression assets, MeasurementSpec references, free parameters, additional roles
and inline payloads are refused.

## Output

A successful run atomically publishes one immutable directory containing:

| Artifact | Schema / content |
|---|---|
| `public_safe_report.json` | `PublicSafeReport v0.1`; only public IDs, aliases and allowlisted claim fields |
| `public_export_manifest.json` | Candidate hash, state and checksum/byte count for the public report |
| `public_export_result.json` | `PublicExportResult v0.1`; state, candidate/report/manifest hashes and scan state |

Every file also appears in `ToolRunV2.artifacts` with its checksum. Measurements
and visualizations are empty. `domain_score=null` and
`score_state=unavailable`.

With no `confirmation_hash`, the state is `ready_for_confirmation`. A second
request carrying the exact candidate hash returns `exported` and writes a new
immutable local run directory; it still performs no upload. A non-matching
confirmation fails without artifacts.

## Allowlist and leak rules

The implementation creates a new object instead of copying and deleting fields.
Internal claim, Evidence, ProductCase, sample and preparation identifiers,
value bindings, source graph references and renderer metadata are never selected.
Every exported claim requires an approved case alias and every source statement
reference must be in the policy allowlist.

The fixed second-line scan rejects server/user paths, `bridge-amax`, credential
or token patterns, email addresses and internal evidence/product/sample/
preparation refs in the rebuilt report, manifest or result.

## Refusal reason codes

- `tool_request_v2_required`, role/schema/version/media-type/checksum failures.
- `verification_receipt_report_binding_mismatch` or
  `claim_verification_result_not_export_eligible`.
- `public_export_policy_inactive`, request report/policy binding mismatch or
  `target_channel_not_allowed`.
- `public_case_alias_missing` or `statement_not_allowlisted`.
- `public_payload_leak_detected` or `confirmation_hash_mismatch`.
- Output-path, input-mutation, existing-bundle and published-hash failures.

## Scope boundary

This is deterministic release packaging, not scientific verification. P0-11
trusts the eligible P0-10 receipt, does not re-evaluate biological truth, and
does not grant public-release authority beyond the supplied frozen policy.
Version 0.2.0 is JSON-only: no CSV, Markdown, ZIP, PDF, HTML, figures or media.
