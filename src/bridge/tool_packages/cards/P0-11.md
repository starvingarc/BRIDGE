# P0-11 Public-safe Export

## Purpose

P0-11 prepares public-facing candidates without uploading them. Version 0.3.0
has two deterministic modes:

- `report_export` rebuilds a P0-10-eligible report through a field allowlist.
- `artifact_audit` inspects candidate JSON, Markdown, CSV, SVG and ZIP files
  against a frozen policy before an Agent presents or exports them.

Both modes are local, checksummed and fail closed on contract violations.

## Contract

| Field | Value |
|---|---|
| Package version | `0.3.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/public-safe-export-run-result/v0.1` |
| Adapter | `bridge.tool_packages.p0_11_public_safe_export.adapter:adapter` |

Both modes accept `ToolRequestV2` and return `ToolRunV2`; contract failures
are reported through typed `reason_codes`.
Use the shared SDK or CLI:

```bash
bridge-tool describe P0-11
bridge-tool input-contract P0-11
bridge-tool validate --request /absolute/path/to/request.json
bridge-tool run --request /absolute/path/to/request.json
```

## Mode: report_export

Exactly four immutable JSON objects are required.

| Role | Schema | Meaning |
|---|---|---|
| `report_draft` | `bridge://schemas/report-draft/v0.1` | Source public-candidate report |
| `claim_verification_result` | `bridge://schemas/claim-verification-result/v0.1` | P0-10 receipt bound to the report |
| `public_export_policy` | `bridge://schemas/public-export-policy-spec/v0.1` | Field, alias, statement and channel allowlists |
| `public_export_request` | `bridge://schemas/public-export-request/v0.1` | Target channel and optional candidate confirmation |

The result publishes `PublicSafeReport`, manifest and export-result JSON files.
Without a confirmation hash it returns `ready_for_confirmation`; an exact
second request returns `exported`. Neither state means network upload or
scientific release.

Example: `examples/requests/p0_11_public_safe_export.json`.

## Mode: artifact_audit

Exactly two immutable JSON objects are required.

| Role | Schema | Meaning |
|---|---|---|
| `public_artifact_audit_policy` | `bridge://schemas/public-artifact-audit-policy/v0.1` | Allowed formats, URLs, JSON Schemas, CSV columns and size limits |
| `public_artifact_manifest` | `bridge://schemas/public-artifact-manifest/v0.1` | Absolute local paths, declared formats, provenance refs and SHA-256 values |

The manifest may contain at most 20 regular files. Supported formats and actual
runtime calls are:

| Format | Executed checks |
|---|---|
| JSON | strict JSON loading, packaged JSON Schema validation, canonical bytes and `hashlib` |
| Markdown | `markdown-it-py`, `regex` and an HTTPS host allowlist |
| CSV | Pandas, Python `csv`, column allowlists and formula-injection rules |
| SVG | `defusedxml`, element/attribute allowlists and URL checks |
| ZIP | Python `zipfile`, archive path/size/symlink rules and `unzip` listing |
| All files | provenance/checksum binding, leak rules, `file` MIME detection and `sha256sum` |

A completed audit returns one path-free `PublicArtifactAuditResult`. Unsafe
content returns `execution_state=succeeded` with `audit_state=blocked` and
typed findings; malformed inputs, checksum changes or unavailable required
runtime tools fail the run.

Example: `examples/requests/p0_11_public_artifact_audit.json`.

## Refusal and boundary

Both modes refuse V1 requests, unsupported roles, wrong schemas or versions,
non-JSON control objects, expression assets, free parameters, unsafe output
paths, checksum mismatches and input mutation.

The package uses deterministic canaries and format rules. A passed result is
not a general privacy proof, biological verification, clinical decision, GMP
release or publication authorization. `domain_score=null` and
`score_state=unavailable`.
