# P0-11 Public-safe Export

## Purpose

P0-11 prepares local public-facing candidates without uploading them. Version
0.4.0 has two deterministic modes:

- `report_export` rebuilds a P0-10-eligible report through an explicit field
  allowlist.
- `artifact_audit` inspects candidate JSON, Markdown, CSV and SVG files under
  registered format and disclosure-pattern rules.

Both modes are checksummed and fail closed when their input contract cannot be
verified. Neither mode grants publication permission.

## Contract

| Field | Value |
|---|---|
| Package version | `0.4.0` |
| Runtime state | `implemented` |
| Scientific state | `candidate` |
| EnvironmentSpec | `ENV-EVIDENCE-v0.2` (`health_check_passed`) |
| Input envelope | `bridge://schemas/tool-request/v0.2` |
| Output envelope | `bridge://schemas/tool-run/v0.2` |
| Result schema | `bridge://schemas/public-safe-export-run-result/v0.1` |
| Adapter | `bridge.tool_packages.p0_11_public_safe_export.adapter:adapter` |

Both modes accept `ToolRequestV2` and return `ToolRunV2`; contract failures
use typed `reason_codes`.

## Mode: report_export

Exactly four immutable JSON objects are required.

| Role | Schema | Meaning |
|---|---|---|
| `report_draft` | `bridge://schemas/report-draft/v0.1` | Source public-candidate report |
| `claim_verification_result` | `bridge://schemas/claim-verification-result/v0.1` | P0-10 receipt bound to the report |
| `public_export_policy` | `bridge://schemas/public-export-policy-spec/v0.1` | Claim-field, alias, statement and channel allowlists |
| `public_export_request` | `bridge://schemas/public-export-request/v0.1` | Target channel and optional candidate-digest value |

The three v0.1 public-candidate outputs remain `PublicSafeReport`,
`PublicExportManifest` and `PublicExportResult`; their existing Schema and
`artifact_count=3` contract are unchanged. The candidate digest is derived
from the public-report bytes, policy hash and target channel. A matching supplied
value only matches that digest. It does not identify who supplied the value,
show that the content was reviewed or constitute approval. The existing
`ready_for_confirmation` and `exported` result labels are retained for
backward compatibility; both describe local state and neither means upload or
release.

The public report always retains structural and provenance fields including
public report/claim IDs, public case aliases, source-report and receipt hashes,
policy reference, target channel and creation time. These hashes are linkable
fingerprints, not evidence of anonymity. The policy-controlled claim-content
matrix covers only `claim_type`, `text`, `language`, `statement_refs`,
`reported_evidence_state` and `comparison_mode`.

## Mode: artifact_audit

Exactly two immutable JSON objects are required.

| Role | Schema | Meaning |
|---|---|---|
| `public_artifact_audit_policy` | `bridge://schemas/public-artifact-audit-policy/v0.1` | Allowed formats, Markdown URLs, JSON Schemas, CSV columns and size bound |
| `public_artifact_manifest` | `bridge://schemas/public-artifact-manifest/v0.1` | Local regular files, declared formats, source refs and SHA-256 values |

The manifest may contain at most 20 files.

| Format | Executed checks |
|---|---|
| JSON | Strict JSON loading, decoded key/value disclosure-pattern scan and packaged JSON Schema validation |
| Markdown | `markdown-it-py`, decoded visible/attribute text scan, GFM-style link discovery and lowercase HTTPS host allowlist; remote images are forbidden |
| CSV | `csv.reader(strict=True)`, decoded cell/header scan, column allowlist and formula guard |
| SVG | `defusedxml`, decoded text/attribute scan, element/attribute allowlists and existing local fragments; external resources are always forbidden |
| All files | One immutable byte snapshot, checksum/source-ref binding, registered path/host/email/credential/internal-ID patterns and `file` media-type detection on a read-only copy |

The Markdown URL allowlist does not apply to SVG and is represented as
`not_applicable` for SVG. A completed audit returns a path-free
`PublicArtifactAuditResult`. A registered rule may block a candidate while the
tool execution itself succeeds; this is not a pass/fail product score.

## Local review visualizations

Each mode also creates exactly two typed local-review figures, each with a
complete TSV fallback and SVG/PNG/PDF renders:

- report export: claim-content field projection; candidate digest and local-file
  state;
- artifact audit: candidate artifact status; artifact-by-registered-check matrix.

The visualization profile uses fixed display IDs such as `Claim 01` and
`Artifact 01`; it excludes claim text values, original artifact IDs, source
references, paths, host names, runtime versions and input IDs. Generated
producer run/result IDs and source/data/config/render hashes remain for exact
lineage binding; they are linkable fingerprints, not anonymity. These local
review figures are not themselves the three-file public report candidate.

## Internal runtime boundary

`ToolRunV2` is an internal execution receipt. Its request and artifact records
contain deployment-local paths. The generic `artifact_manifest.json` has
`scope=internal_run_provenance` and contains environment and structured-input
hashes. Neither object may be exposed as a public-safe download. A UI may expose
only an explicitly selected public candidate or the P0-11 visualization artifact
set, never every entry in `run.artifacts`.

The registered-pattern scanner is a bounded gate, not comprehensive
de-identification. It does not identify arbitrary names, phone numbers or
context-sensitive fields. Public aliases, claim text, statement references and
policy references must therefore come from controlled orchestration and an
eligible P0-10 receipt. P0-11 does not authenticate reviewers or policy
authors.

PublicSafeReport claim text remains an ordinary string. Web clients must render
it as escaped plain text; they must not inject it directly as HTML or Markdown.
A no-block result is not proof that an arbitrary renderer is XSS-safe.

## Refusal and boundary

The package refuses V1 requests, unsupported or mixed roles, wrong schemas or
versions, expression assets, free parameters, unsafe output paths, checksum
changes, metadata that matches a registered disclosure pattern and input
mutation. It validates source-reference syntax but not the producer registry or
source truth.

“No registered rule blocked” is limited to the checks that actually ran. It is
not a general privacy, safety, biological, clinical, GMP or publication
decision. `domain_score=null` and `score_state=unavailable`.

Use the shared SDK or CLI:

```bash
bridge-tool describe P0-11
bridge-tool input-contract P0-11
bridge-tool validate --request /absolute/path/to/request.json
bridge-tool run --request /absolute/path/to/request.json
```
