# P0-06 Proliferation & Stress Response

## Purpose

Execute externally configured expression-program methods or aggregate precomputed
whole-product and state-specific evidence. Product-bound modes produce a
deterministic, stage-aware candidate profile. The separate exploratory mode
below measures supplied S/G2M programs without making a product assessment.

| Field | Value |

```bash

```

The committed examples contain placeholder paths and checksums:
`p0_06_proliferation_stress_response.json` documents legacy aggregation;
`p0_06_process_method_runtime.json` documents real expression-method execution.


## Exploratory selected-view mode

P0-06 v0.8.1 also accepts exactly one `exploratory_process_input`
(`bridge://schemas/exploratory-process-input/v0.1`, object_version `0.1.0`)
and one checksummed scRNA/snRNA H5AD. The input binds the exact DataView,
observation count/digest, matrix declaration, gene-symbol column, source family,
versioned resource reference/hash, exact S/G2M lists and their content hashes.
List hashes use UTF-8 symbols in supplied order joined by LF, with a final LF.
Source references are caller declarations; runtime verifies content correspondence,
not source authorship or QC acceptance. No live resource lookup or alias replacement.
The original unique H5AD feature IDs remain the scoring index. Requested symbols
are resolved only through the supplied column to one exact feature ID; the
mapping is recorded. Ambiguous requested symbols are not assessed. Repeated
non-program symbols remain distinct original features in the complete control
universe, and their count is reported. No count collapsing or symbol suffixing
occurs. This follows the gene-ID indexing option in the
[official Scanpy reader](https://scanpy.readthedocs.io/en/stable/generated/scanpy.read_10x_mtx.html).

This mode measures the supplied S/G2M sets with Scanpy program scoring, decoupler
ULM, Scanpy cell-cycle prediction and descriptive selected-view phase aggregation.
It requires complete gene coverage. Missing genes and method failures produce
`not_assessed` values with explicit reasons, not zero counts or discarded cells.
Raw counts use the same in-memory 10,000/log1p recipe. Program Scanpy parameters
are ctrl_size 50, n_bins 25 and ctrl_as_ref true; cycle ctrl_size is the smaller
supplied phase-list length. All calls explicitly use the selected matrix rather
than `.raw`, and the request seed is recorded. ULM uses tmin 5, unit-weight
membership and empty=false to retain the full feature/observation universe.
Quantiles 0.1/0.9 describe cells, not confidence intervals.

The new `proliferation-stress-response-result/v0.1` result union preserves old
v0.3 profile payloads and adds `ExploratoryProcessProfile` v0.1. Exploration
publishes aggregate JSON, per-observation Parquet and an artifact manifest.
It produces no gate-facing MeasurementResult, product profile, reviewed state,
biological-unit assignment, alert, purity estimate or qualification decision.
State review stays pending, independence unknown, independent n null and
domain_score null. Other modes retain their original review and attestation
requirements. Exploratory mode rejects product-review/MeasurementSpec roles;
it is not an alternate way to satisfy their gates.

Both program scorers and predicted phases share one expression evidence family.
Their numeric units are not combined, and method count is not evidence count.
A predicted S/G2M fraction is not a division rate; G1 is not proof of G0 or
quiescence. No stress program is assessed without a supplied, reviewed resource.
This first mode intentionally implements only the approved S/G2M resource pair.
It adds no dedicated Web builder or visualization family; source SDK support,
installed UI support and genuine execution are reported separately.

## Structured inputs

Legacy aggregation requires seven immutable `application/json` objects and may
accept one independent P0-06 `MeasurementSpecV2`. Every `StructuredInputRef`
requires an absolute regular-file path, exact lowercase SHA-256 checksum,
Schema URI and matching object version.

| Role | Schema | Main fields and lineage |
|---|---|---|
| `product_case` | `bridge://schemas/product-case/v0.1` | Product definition, assay, source unit and MeasurementSpec refs |
| `product_definition_card` | `bridge://schemas/product-definition-card/v0.1` | Product definition/version and supported assay |
| `development_window_spec` | `bridge://schemas/development-window-spec/v0.1` | P0-04-owned candidate/confirmed window, assay, state-map and rationale binding |
| `program_spec` | `bridge://schemas/program-spec/v0.1` | Authoritative program targets/weights or S/G2M genes, their canonical content SHA-256, source ref, allowed scopes/states/stages/metrics, coverage threshold, LOD states, review mapping and attribution counts |
| `cell_state_evidence_profile` | `bridge://schemas/cell-state-evidence-profile/v0.2` | Upstream state evidence, assay and MeasurementSpec binding |
| `protocol_ir` | `bridge://schemas/protocol-ir/v0.1` | Metadata completeness, batch confounding, independent-replicate/comparison counts and declared process-step IDs |
| `program_evidence_bundle` | `bridge://schemas/program-evidence-bundle/v0.1` | Precomputed records plus IDs and checksums binding all six upstream objects |
| `measurement_spec` (optional) | `bridge://schemas/measurement-spec/v0.2` | Legacy projection contract; `tool_refs` must equal `[P0-06]` and `metric_ids` / `analysis_scopes` must exactly cover ProgramSpec |

### Method runtime additions

| Input | Contract |
|---|---|
| Selected expression view | Exactly one checksummed H5AD matching the P0-02 V3 DataView. It may be analysis-ready `normalized_expression`, or count-ready integer `raw_counts`, which P0-06 normalizes in memory with deterministic library-size 10,000 scaling and `log1p`. |
| `cell_state_evidence_profile` | V3 profile binding the selected DataView and biological-unit manifest |
| `biological_unit_manifest` / `biological_unit_assignment` | Immutable P0-01-declared observation-to-analysis-unit and independence-group mapping |
| `biological_unit_attestation_receipt` | Caller/data-owner `analysis_execution` assertion bound to the exact manifest, assignment, DataView, observation set and external attestation trace |
| `process_method_spec` | Selected method IDs, program ID selectors, scopes and runtime/summary parameters; it does not duplicate program genes, weights or phases |
| `process_method_input` | v0.1 keeps caller assignments for `method_runtime`; v0.2 requires a P0-02 manifest/evidence descriptor for `method_runtime_source_bound` and contains no parallel caller row list |
| `measurement_spec` | Required P0-06-only gate contract. Assay, observation/analysis/independence units, selected scopes, metric names, score units and source method IDs must exactly match the bound method inputs. |

Both method modes have twelve structured inputs in total and do not accept a caller-
provided ProgramEvidenceBundle. Exact process_method_input Schema/version selects
method_runtime (v0.1/0.1.0) or method_runtime_source_bound (v0.2/0.2.0); mixed
pairs fail. Source-bound mode checks the canonical P0-02 evidence Parquet and
same-run manifest, preserves consensus/single-source/conflict/unavailable
semantics, includes every row in whole-product denominators, and excludes
unresolved/unavailable or disallowed candidates only from state-specific groups.
This establishes bundle correspondence, not independent authentication. The attestation receipt must be `confirmed` and
all four biological-unit design confirmations must be present. Runtime validates
its structure and immutable content bindings only; deployment authenticates the
referenced conversation or workflow record. The exact DataView matrix location is
enforced;
`ProcessMethodSpec.expression_layer` cannot select a different H5AD matrix.

For raw-count inputs, the method bundle records
`normalization_recipe_id=bridge_normalize_total_log1p_v0.1` and
`normalization_target_sum=10000.0`. This is a versioned package recipe under
P0-06, not a knowledge-catalog Method reference.

The runtime calls `scanpy.tl.score_genes`, `decoupler.mt.ulm` and
`scanpy.tl.score_genes_cell_cycle`, then aggregates scores and phase counts
by declared analysis unit and optional candidate cell state. It emits means,
medians, quantiles, gene coverage, denominators, execution provenance and
cross-method Spearman agreement. UCell, AUCell, pseudobulk and CNV tools are
registered candidates but are not executed by this adapter.

The external `ProgramSpec` is authoritative for every program ID, gene/weight
or S/G2M phase definition, source reference, applicable stage/state/scope,
metric ID, coverage threshold, LOD rule, review outcome and follow-up reference.
`ProcessMethodSpec` only selects those program IDs and configures execution.
None of these biological choices is encoded in the adapter.

For a weighted program, `gene_set_sha256` is the SHA-256 of canonical UTF-8
JSON containing `content_type=weighted_program_targets` and gene-sorted
`targets`. For a cell-cycle program it hashes
`content_type=cell_cycle_phase_genes` plus sorted `s_genes` and `g2m_genes`.
Canonical JSON sorts keys, uses compact separators and rejects non-finite
numbers. Changing a gene, weight or phase gene while retaining the old digest
is refused as `program_gene_set_content_checksum_mismatch` or
`cell_cycle_gene_set_content_checksum_mismatch`; missing selected content uses
`process_program_content_missing` or `cell_cycle_program_content_missing`.

The legacy `measurement_spec_ref` request parameter, arbitrary parameters,
missing or duplicate required roles,
unsupported media, checksum/version/Schema drift, ProductCase or
ProductDefinition mismatch, cell-state MeasurementSpec mismatch, unregistered
methods and evidence outside the external spec are refused. Method mode also
refuses caller-provided precomputed evidence, DataView/matrix drift, invalid raw
counts, asset replacement, observation-lineage drift, a missing, unconfirmed or
misbound biological-unit attestation receipt, an incompatible P0-06
MeasurementSpec,
missing selected program content and program-content checksum drift.

## Evaluation and output

In method mode, program targets, weights, thresholds, scopes and cell-cycle
genes come only from the checksummed `ProgramSpec`; the method spec contains
selectors and execution parameters only. The adapter contains no biological
cutoff, state definition or review-rule promotion.

For legacy aggregation, P0-06 evaluates each precomputed record in a fixed
order:

1. stage and state applicability;
2. gene coverage against the external threshold;
3. LOD against externally allowed/resolvable states;
4. the external evidence-state-to-review-outcome mapping;
5. process-attribution eligibility.

Missing process metadata, unresolved batch confounding or insufficient
replicate/comparable-group counts produce `cannot_attribute`. The count
requirements are external ProgramSpec fields. In `method_runtime`, the declared
`ProtocolIR.independent_replicate_count` cannot exceed the number of distinct
independence groups in the bound `BiologicalUnitManifest`; an over-declaration
is refused as `protocol_independent_replicate_count_exceeds_manifest`. Equal or
lower declared counts continue through the existing conservative rule. Low coverage produces
`unavailable`; unresolved LOD produces `cannot_resolve`; neither becomes
zero or a negative biological finding.

Legacy results contain checksum source bindings, `ProgramEvidenceSummary[]` and
aligned `TranscriptomicReviewFlag[]`.
Review states are `transcriptomic_review_flag`,
`not_detected_above_lod`, `cannot_resolve` or `not_assessed`, and every
flag remains `shadow`. An untriggered rule carries the invariant
`not_evidence_of_safety`.

Each run publishes checksummed JSON artifacts. Method mode derives its
gate-facing measurements directly from the method bundle:

- `proliferation_stress_response_profile.json`;
- `program_measurement.<token>.json` for every legacy evidence result when its
  optional MeasurementSpec is supplied;
- `method_measurement.<kind>.<token>.json` for every real `ProgramScoreSummary`
  and `CellCycleSummary` in method mode;
- `process_method_bundle.json` (method mode only; v0.2 binds the exact selected
  DataView matrix, input semantics, any package-owned normalization, ProgramSpec,
  method spec/input, expression asset and BiologicalUnit inputs);
- `artifact_manifest.json`.

Successful runs also publish package-owned typed visualization data, exact TSV
fallbacks, deterministic SVG/PNG/PDF renders and a visualization artifact set
for three registered views:

- stage- and cell-state-conditioned program evidence, including gene coverage,
  applicability, evidence state and review state;
- method-separated program-score summaries across declared analysis units;
- cell-cycle phase composition and S/G2M score evidence across declared units.

When a view has no applicable runtime records, it remains explicitly
`not_assessed`; the renderer does not create replacement values. The current
contract has no numeric reference envelope, ordered ProtocolIR timeline,
numeric LOD/UCB or spike-in recovery curve, and no CNV visualization.

Repeated identical inputs reuse byte-identical output. Input replacement or
existing-bundle drift fails closed with a typed reason code. P0-06 v0.7 emits
profile v0.3. Legacy mode without a MeasurementSpec records `not_requested`;
with one, it preserves every original evidence record and applies the historical
state projection. Method mode requires its own MeasurementSpec and emits one
`MeasurementResultV2` per actual method summary: an available program mean or
cycling fraction becomes `inferred`; a `not_assessed` summary becomes numeric-
null `unavailable`. Program-score means retain their observation denominator and score-sum numerator; cell-cycle counts retain their numerator and denominator. Every
binding records the source summary hash, method, program, scope and biological
unit. All projections use `score_state=unavailable` and `domain_score=null` and
introduce no biological threshold, alert or safety interpretation. Historical
profile v0.1/v0.2 and method-bundle v0.1 Schemas remain packaged but are not the
default v0.7 payloads.

## Scientific boundary

The registered implementation methods execute Scanpy and decoupler baselines,
deterministic sample/state aggregation and design auditing. Successful software
execution does not make the selected gene programs, thresholds or biological
interpretations scientifically validated.

The profile always remains `descriptive_only`, `candidate/shadow`,
`domain_score=null` and `score_state=unavailable`. A transcriptomic review
flag is a request for orthogonal review, not evidence of tumorigenicity, genomic
abnormality, clinical risk or product failure. P0-06 does not establish safety,
potency, efficacy, GMP release or product rank.
