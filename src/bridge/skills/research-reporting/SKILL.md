# Research reporting

## Scope and inputs

Deliver an answer that can be traced to one current analysis version. Read current
graph/evidence state, explanation binding, report preparation/handoff and verifier
receipt. Scientific writing quality, evidence verification and release permission
are separate. An existing report file alone establishes none of them.

## Decisions

1. Establish the question, audience and requested deliverable. Use existing results
   only for their actual version and scope. If the request only asks about reporting
   conditions, explain them briefly without preparing a new run.
2. Organize available evidence into findings, figures, methods, sources, limitations
   and useful next actions. Keep incomplete/unassessable domains visible. Copy
   numeric meaning only from tool-owned observations: units, denominator, uncertainty
   and descriptive/candidate status must survive prose compression.
3. In approved assessment, follow the server-owned phase. If
   `report_preparation.state=graph_required`, select useful supplied graph/sufficiency
   preparation options. Graph execution must precede the current report explanation.
4. If a current cited explanation is required, use the evidence-reasoning contract
   and end that phase. A later explicit resume may offer the report option. When
   `workflow_handoff.state=report_ready_after_current_explanation`, select the supplied
   P0-10 option; repeating an old explanation is not progress toward that report.
5. In ordinary conversation, use existing report controls or an eligible registered
   plan only when report generation is requested. Preparation still waits for its
   exact approval. A narrative `reply` is not P0-10 execution or claim verification.
6. Inspect the actual verifier receipt. A succeeded tool run may still yield
   `release_blocked`; explain its concrete missing prerequisite or claim restriction.
   A corrected fact/version requires impact review and an approved update, preserving
   historical artifacts rather than silently rewriting the report.

## Stopping and output

Present concise findings and figure/report entry points with sources, limitations and
next steps. Keep methods and detailed numbers available through existing views.
If source binding, current explanation or verification is missing, give that gap and
the next feasible action. Do not fill absent results, references or approval statements.
Private report generation, public-safe export and external publication are different
operations; use the existing explicit controls for each.
